## Посмотрим на данные

Функция `check_project(root)` запускает Python как отдельный процесс в папке учебного проекта. `returncode=0` означает успешное завершение команды; ненулевой код - проблему. В нашем примере тесты проверяют расчёт цены, поэтому успешный запуск подтверждает именно эти сценарии, а не любые свойства предложенного кода.

```python
command = [sys.executable, '-B', '-m', 'unittest', 'discover', '-s', 'tests']
# sys.executable - тот же Python, которым запущен наш demo.py.
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

Теперь запустим уже знакомые тесты как действие нашей программы. Команда запуска в каркасе подготовлена: её не нужно собирать строкой или передавать в командную оболочку. Получим результат отдельного процесса и преобразуем его в понятный словарь.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть - вторую функцию с тем же именем создавать не нужно.

```python
def check_project(root: Path) -> dict:
    command = [sys.executable, '-B', '-m', 'unittest', 'discover', '-s', 'tests']
    process = subprocess.run(
        command,
        cwd=root,
        capture_output=True,
        text=True,
        encoding='utf-8',
        errors='replace',
        timeout=5,
    )
    return {
        'passed': ...,
        'returncode': process.returncode,
        'output': ...,
    }
```

В `passed` подставьте `process.returncode == 0`. В `output` соедините `process.stdout + process.stderr`: тесты могут писать сообщения в оба потока. `subprocess.run` ждёт завершения процесса и возвращает объект с этими полями.

`cwd=root` выбирает папку запуска; `capture_output=True` собирает вывод вместо немедленной печати; `text=True` возвращает строки; `encoding` и `errors` задают чтение текста; `timeout=5` ограничивает ожидание пятью секундами. Эти настройки уже показаны готовым блоком. `-m unittest discover -s tests` означает запуск тестов из папки `tests` через текущий Python.

На исходном `prices.py` результат `passed=False` ожидаем: в нём ещё ошибочное сложение. После согласованной замены на умножение ожидаем `True`. Не превращайте любой результат запуска в успех и не запускайте здесь неизвестные проекты: наши ограничения пути не изолируют Python-процесс от операционной системы.

## Найдём файл запуска и проверим результат

В левой панели **Project -> lesson-05-04-verify -> demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка «запустить проект» нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View -> Tool Windows -> Project**. Если Run скрыто - **View -> Tool Windows -> Run**.

До завершения функции появится сообщение «Допишите ... по подсказкам урока». После реализации ожидаем:

```text
На исходном ошибочном prices.py: passed = False. После применения правильного исправления: passed = True.
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

## Соберём итоговый проход

После реализации `check_project` в том же корне откройте `demo_agent.py`. Он соединяет готовые части: получает предложение, показывает diff, проверяет согласие, записывает файл и запускает тесты. В начале файла `USE_LIVE_MODEL = False` оставляет учебное предложение из `coding_model.py`, а `APPROVED = False` запрещает запись. Запустите его сначала так и прочитайте diff в Run.

Для проверки записи на приложенном учебном `workspace/prices.py` можно изменить только `APPROVED` на `True` и повторить Run. Успешные тесты должны подтвердить расчёт `100 × 3 = 300`. Повторный запуск после исправления может показать пустой diff: код уже совпадает с предложенным. Для исходного состояния откройте новую распаковку архива.

Если у вас уже настроен доступ из второго подпроекта, `USE_LIVE_MODEL = True` выберет сетевой адаптер `propose_live`. Правила передачи ключа остаются прежними. В этой версии один проход «прочитать -> предложить -> согласовать -> проверить»: самостоятельного исправления по результатам тестов пока нет. И ни проверка путей, ни слово «учебный» не заменяют отдельную изолированную среду для неизвестного кода.

Сейчас ваша работа - `check_project` в `workspace.py`; затем повторный запуск `demo.py`.
