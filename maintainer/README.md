# Сопровождение курса

Читательский вход — корневой README и `course/README.md`. В этой папке хранятся решения о сборке и проверках, чтобы при продолжении работы не восстанавливать контекст по диалогу.

- `WORK_LOG.md` — что подготовлено, что проверено и какие ограничения остались.
- `export-manifest.json` — состав последнего экспорта с контрольными суммами файлов.
- `../tools/course-map.json` — соответствие заметок Obsidian страницам GitHub, архивам и исходникам.

## Обновить материалы из Obsidian

В корне репозитория выполните:

```powershell
python tools/export_obsidian.py --vault 'путь-к-корню-хранилища'
python tools/check_course.py
```

Команда читает только заметки читательского курса и материалы, на которые они ссылаются. Рабочие итерации, история чата и соседние разделы хранилища сюда не копируются. Относительные ссылки, изображения и раскрывающиеся блоки преобразуются для GitHub.

Если экспортируемый файл изменён вручную в репозитории, экспорт остановится до записи. Сначала сравните изменения и перенесите нужное в исходный материал; не стирайте решение ученика ради пересборки. `README.md` в корне и этот журнал редактируются отдельно и не генерируются из Obsidian.

## Что проверяется

`tools/check_course.py` проверяет локальные ссылки, синтаксис Python, целостность архивов, совпадение кода архива с папкой упражнения и ожидаемое поведение незавершённых демонстраций. Проверка не вызывает API и не оценивает ответы модели. Успех сборки не означает, что все учебные функции реализованы.

Проверки решений расположены в `exercises/lesson-…/tests/test_lesson.py`. Их запускает читатель после выполнения соответствующего задания. До этого они закономерно не проходят.
