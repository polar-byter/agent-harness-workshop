# Урок 4. Соединяем чтение, поиск и журнал

[Открыть исходники этого урока](../../exercises/lesson-01-04-run/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-01-04-run/TASK.md)

> **Где мы.** У помощника есть три отдельные функции: чтение регламента, поиск и запись в журнал. Соберём из них одну операцию, которую потом сможет вызывать агент.
> `[файл -> чтение -> поиск -> журнал]` -> результат

Пока чтобы найти пункты о возврате, приходится по очереди вызывать три функции и не перепутать порядок. Агенту в третьем разделе понадобится одна команда "найди", после которой всё остальное программа сделает сама. Заодно добавим к результату статус: `found`, если пункты нашлись, и `not_found`, если нет. По статусу сразу видно исход поиска, не разглядывая список.

## Посмотрим на данные

В `demo.py` уже указаны путь к регламенту `data/notes.txt`, запрос `' возврат '` и путь к журналу `runs.jsonl`. Функция `run_search` получит эти три значения и вернёт словарь с запросом, статусом и найденными пунктами.

Статус вычисляется одной строкой:

```python
status = 'found' if matches else 'not_found'
```

Если список `matches` не пустой, получится `'found'`, а для пустого списка `[]` - `'not_found'`.

## Напишите сами

В `run_search` уже прочитан регламент и найдены пункты: результат лежит в `matches`. Замените `raise NotImplementedError(...)` кодом ниже и заполните пропуски:

```python
    status = 'found' if matches else 'not_found'
    result = {
        'query': ...,
        'status': ...,
        'matches': ...,
    }
    write_result(..., ...)
    return result
```

1. В `'query'` положите запрос без пробелов по краям: `query.strip()`.
2. В `'status'` и `'matches'` - переменные `status` и `matches`.
3. `write_result` получает сначала путь к журналу `journal_path`, затем словарь `result`.

Слева от двоеточия в словаре стоят имена полей в кавычках, справа - значения; здесь значениями служат переменные. Запись в журнал стоит после чтения и поиска не случайно: если файл не найден, функция остановится раньше, и в журнал не попадёт запись о поиске, которого не было.

## Запустим

Откройте `demo.py`, нажмите правой кнопкой в коде и выберите **Run 'demo'**. В окне Run появится:

```text
{'query': 'возврат', 'status': 'found', 'matches': ['Возврат товара возможен в течение 14 дней.', 'ВОЗВРАТ денег производится на карту покупателя.', 'Для возврата нужен чек или номер заказа.']}
```

Пунктов три: слово "возврат" входит и в "возврата", поэтому нашёлся пункт про чек. Наш поиск ищет часть строки, а не целое слово. Для регламента это скорее удобно, но в других задачах такое поведение может дать лишние совпадения.

## Попробуйте сломать

1. Замените запрос в `demo.py` на `'гарантия'`. Статус станет `not_found`, список пустым, а в журнал всё равно добавится запись: поиск выполнен, просто ничего не нашёл.
2. Замените путь к регламенту на `ROOT / 'data' / 'missing.txt'`. Программа остановится с `FileNotFoundError`, и в журнал ничего не запишется.

Сравните два случая в `runs.jsonl`: неудачный поиск оставил след, а отсутствующий файл - нет. Верните прежние значения.
