> **Где мы находимся:** В прошлом уроке мы научились готовить сообщения для модели. 
> 
> Когда сервис модели присылает ответ, он возвращает не просто готовую строчку текста, а сложный вложенный словарь со статусами, метаданными и частями генерации. 
> 
> В этом уроке мы напишем функцию `extract_answer`, которая безопасно достает чистый текст ответа и проверяет, что генерация не оборвалась на полуслове:
> 
> `Сырой JSON-ответ сервиса -> [extract_answer] -> чистый текст ответа клиенту`

---

## Что лежит в сыром ответе сервиса?

В папке `data` урока лежит файл `response.json`. Давайте откроем его и посмотрим, как выглядит настоящий ответ API:

```json
{
  "status": "completed",
  "output": [
    {
      "type": "message",
      "content": [
        {
          "type": "output_text",
          "text": "Списки Python сохраняют порядок элементов."
        }
      ]
    }
  ]
}
```

Почему структура такая вложенная?
1. В ответе могут приходить служебные блоки (например, мысли модели или вызовы инструментов). Нам нужно отобрать только блоки с типом `output_text`.
2. Текст ответа может приходить несколькими кусочками, которые нужно аккуратно склеить.
3. Поле `status` сообщает, завершился ли ответ успешно (`"completed"`). Если статус другой (например, генерация оборвалась из-за ошибки сети или тайм-аута), программа не должна отдавать клиенту обрубок фразы.

3. В конце верните очищенную строку: `answer`.

## Под капотом: безопасная работа со словарями через `.get()`

Обратите внимание на использование метода `.get()`:
```python
response.get('status')
item.get('content', [])
```
Почему не прямой доступ через квадратные скобки `response['status']`?
Если сервис вернет неожиданный формат или в ответе не окажется ключа `content`, обращение `item['content']` немедленно уронит программу с фатальной ошибкой `KeyError`.

Конструкция `.get('content', [])` безопасна: если ключа нет, она просто вернет пустой список `[]`, внутренний цикл `for` ни разу не выполнится, и программа спокойно продолжит работу.
