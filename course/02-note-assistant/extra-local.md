# Запускаем модель прямо из Python

[Открыть исходники этого урока](../../exercises/lesson-02-extra-local/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-02-extra-local/TASK.md)

> **Где мы.** В основном уроке программа отправляла сообщения в Ollama, а та запускала модель. Здесь попробуем загрузить модель в саму программу. Урок необязательный, основной маршрут продолжается через Ollama или облачный сервис.

До сих пор модель работала в отдельном приложении, а наш код только посылал ей запросы. Можно устроить иначе: загрузить файл модели прямо в программу на Python. Тогда загрузка модели, вызов и освобождение памяти становятся обязанностью нашего кода. Так бывает, например, когда модель встраивают в программу, которую нельзя подключать к сети.

Вопрос и данные возьмём прежние: "Сколько дней есть на возврат товара?" и пункт "Возврат товара возможен в течение 14 дней." Функции `build_messages` и `extract_answer` останутся без изменений: ответ модели мы приведём к знакомому формату. Напишем только `send_local` - функцию, которая вызывает загруженную модель.

## Кто будет выполнять вычисления

Считать будет движок llama.cpp, а библиотека `llama-cpp-python` даёт к нему доступ из Python. В готовом пакете для Windows движок уже собран, поэтому компилировать ничего не придётся.

Модель хранится в файле формата GGUF: внутри обученные числовые параметры и служебные сведения для загрузки. Возьмём Qwen3-0.6B в варианте Q8_0 из [официального репозитория Qwen](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/tree/main). Семейство знакомо по Ollama, но теперь мы сами выбираем конкретный файл. Разные варианты одного семейства и разные настройки запуска дают разные ответы.

После установки библиотеки и скачивания файла модель работает на процессоре без интернета. Памяти ей понадобится больше, чем весит файл: кроме параметров модели, место занимает обработка сообщений.

## Подготовим библиотеку и файл модели

Маршрут рассчитан на Windows x64 и Python 3.14. В файле `requirements.txt` записан адрес готовой сборки `llama-cpp-python` 0.3.36, поэтому установка не начнёт собирать C++. Способ установки готовых пакетов описан в [документации библиотеки](https://llama-cpp-python.readthedocs.io/en/latest/).

Для этой папки используйте отдельное виртуальное окружение `.venv`: библиотеки установятся только сюда, и остальные проекты курса не изменятся.

1. Откройте **View -> Tool Windows -> Terminal** и убедитесь, что терминал открыт в папке `lesson-02-extra-local`. Если PyCharm ещё не создал окружение, откройте **Settings -> Project -> Python Interpreter -> Add Interpreter**, выберите **Virtualenv** и создайте его в `.venv`, указав Python 3.14 как основу.
2. Введите команду. Флаг `--only-binary=:all:` разрешает только готовые пакеты:

```powershell
python -m pip install --only-binary=:all: -r requirements.txt
```

3. Откройте `check_install.py` и выберите **Run 'check_install'**. В окне Run появятся путь к Python и строка `Библиотека загружена: 0.3.36`. Если терминал сообщил об успешной установке, а этот запуск библиотеку не нашёл, значит, они работают с разными интерпретаторами. Выберите в настройках `.venv` этой папки и повторите установку в заново открытом терминале.
4. Откройте [страницу файла Qwen3-0.6B-Q8_0.gguf](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF/blob/main/Qwen3-0.6B-Q8_0.gguf) и нажмите **download** рядом с описанием. Файл весит около 639 МБ.
5. Переместите скачанный `Qwen3-0.6B-Q8_0.gguf` в папку `lesson-02-extra-local\models`, не меняя имени. В **Project -> models** он должен появиться рядом с `README.md`.

Если установка сообщает, что подходящего пакета нет, сверьте версию и разрядность Python со строкой выше: каркас рассчитан на Windows x64. Если ошибка касается соединения с GitHub или Hugging Face, проверьте, открываются ли эти сайты в браузере.

## Посмотрим, что уже подготовлено

Откройте `local_runtime.py`. В функции `load_model` создаётся объект модели:

```python
model = Llama(
    model_path=str(path), n_ctx=2048, n_gpu_layers=0,
    seed=42, verbose=False,
)
```

`Llama` - класс библиотеки, через созданный объект мы будем обращаться к загруженной модели. `model_path` - путь к файлу GGUF, `n_ctx` - размер контекста, `n_gpu_layers=0` оставляет вычисления на процессоре, `verbose=False` убирает подробный диагностический вывод. `seed=42` задаёт начальное значение генератора случайных чисел: на одном компьютере ответы будут повторяться, на другой сборке могут отличаться. Все параметры описаны в [справке класса Llama](https://llama-cpp-python.readthedocs.io/en/latest/api-reference/#llama_cpp.Llama).

Модель загружается один раз перед обращением, внутри блока `with load_model(...) as model` в `demo.py`. При выходе из блока `load_model` освобождает память, даже если по пути случилась ошибка. Каждый новый Run запускает программу заново и загружает модель снова. Историю прошлых вопросов объект модели сам не хранит: если она нужна, программа должна передать её в сообщениях.

Сообщения, как и раньше, собирает `build_messages`: правило с ролью `developer` и данные с ролью `user`. Готовая `prepare_messages` копирует их, меняет роль `developer` на `system` и добавляет к правилу короткую команду Qwen `/no_think`. Она переключает модель в режим ответа без развёрнутых рассуждений; сам текст правила не меняется. Переключатель описан в [карточке модели Qwen](https://huggingface.co/Qwen/Qwen3-0.6B-GGUF#switching-between-thinking-and-non-thinking-mode).

## Напишите сами

Откройте `local_model.py`. У `send_local` два параметра: `model` - загруженный объект модели, `messages` - список сообщений. Строка `prepared = prepare_messages(messages)` уже есть. Замените следующую за ней строку `raise NotImplementedError(...)` фрагментом ниже и заполните два пропуска:

```python
    response = model.create_chat_completion(
        messages=...,
        max_tokens=256,
        temperature=0.7,
        top_p=0.8,
        top_k=20,
        min_p=0.0,
        presence_penalty=1.5,
    )
    return convert_response(...)
```

1. В `messages=` поставьте `prepared`.
2. В `convert_response(...)` передайте `response`.

`model.create_chat_completion(...)` - метод загруженной модели: он передаёт сообщения движку и возвращает словарь с результатом. HTTP-запроса и Ollama здесь нет, всё происходит внутри нашей программы. Код должен стоять внутри `send_local` с отступом в четыре пробела; `return` начинается на том же уровне, что `response = ...`.

`max_tokens=256` ограничивает длину ответа. Остальные настройки подобраны для Qwen, их не меняем, чтобы сравнивать способы подключения на одной задаче.

<details>
<summary>Что означают настройки выбора следующего токена</summary>

`temperature` влияет на то, насколько смело модель выбирает менее вероятные продолжения. `top_k` ограничивает число кандидатов, `top_p` отбирает их по суммарной вероятности, `min_p` задаёт относительный порог, здесь он отключён значением `0.0`. `presence_penalty` снижает оценку уже встречавшихся токенов и сдерживает повторы. Все эти настройки меняют стиль генерации, но правильность ответа не проверяют. Описание - в [справке create_chat_completion](https://llama-cpp-python.readthedocs.io/en/latest/api-reference/#llama_cpp.Llama.create_chat_completion).

</details>

## Проследим обратный путь

Библиотека возвращает результат в структуре с полем `choices`. Упрощённо она выглядит так:

```python
{'choices': [{'finish_reason': 'stop', 'message': {
    'content': 'Вернуть товар можно в течение 14 дней.'
}}]}
```

`choices[0]` - первый вариант ответа, `message['content']` - его текст. Готовая `convert_response` проверяет, что генерация завершилась (`finish_reason` равен `stop`), убирает служебный блок `<think>...</think>`, если Qwen его всё-таки вывела, и приводит ответ к знакомой структуре со `status` и `output`. Затем `extract_answer` достаёт строку. Благодаря общему формату функцию извлечения не пришлось переписывать при смене способа подключения. Сверять ответ с пунктом регламента `convert_response` не умеет: это по-прежнему наша проверка.

## Сначала проверим код, затем получим настоящий ответ

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Вместо модели здесь отвечает маленький подготовленный объект, поэтому файл GGUF и библиотека не нужны. Проверка убеждается, что функция передала правильные сообщения и вернула ожидаемую структуру. После реализации в Run будет:

```text
Проверка без модели: Вернуть товар можно в течение 14 дней.
```

Теперь откройте `demo.py` и выберите **Run 'demo'**. В Run появятся вопрос и пункт регламента, затем строка `Загружаем модель из файла...`. Дождитесь строки `Ответ модели:`; на скорость влияет мощность компьютера. Слова ответа могут отличаться от контрольного примера: проверьте, называет ли модель срок 14 дней и не добавляет ли сведений, которых нет в пункте.

Если видите `Допишите send_local...`, заглушка осталась на месте. Если программа просит положить файл модели по указанному пути, проверьте папку `models` и имя файла. Сообщение о незавершённой генерации значит, что модель упёрлась в лимит длины, и оборванный текст программа за ответ не выдаёт.

## Попробуйте изменить источник

Оставьте тот же вопрос, но замените пункт в `demo.py` на `'Возврат товара возможен в течение 30 дней.'`. Источник теперь говорит о другом сроке, и ответ должен измениться вслед за ним. Если модель по-прежнему пишет про 14 дней, значит, она отвечает не по переданному пункту: прошлый запуск в новый запрос не попадает, сообщения собираются заново. Маленькие модели такое себе иногда позволяют, и именно поэтому ответ сверяют с источником, а не только смотрят, что текст появился. После опыта верните исходный пункт.

## Как это связано с будущим агентом

Здесь мы поменяли только способ выполнить одно обращение к модели: вместо Ollama файл загружает сама программа. Вопрос и пункт регламента мы по-прежнему задаём заранее. В [уроке об агентном цикле](../03-tool-agent/02-cycle.md) программа начнёт возвращать модели найденные пункты и снова спрашивать, что делать дальше. Вызов через API, Ollama или библиотеку в таком цикле занимает одно и то же место: получает сообщения и возвращает очередное решение модели. Сам цикл и правила выполнения пишет наше приложение.

Это упражнение не меняет сохранённое подключение для остальных каркасов. Основной маршрут продолжается [первым уроком об инструментах](../03-tool-agent/01-tools.md).
