# Урок 2. Показываем предлагаемое изменение

[Открыть исходники этого урока](../../exercises/lesson-05-02-diff/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-05-02-diff/TASK.md)

> **Где мы.** Агент получает доступ только к файлам рабочей папки. Теперь он предлагает исправить `prices.py`, и прежде чем что-то записывать, программа покажет человеку, что именно изменится.
> `предложение модели -> [diff для человека] -> согласие -> запись -> проверка`

В `prices.py` стоимость заказа считается сложением цены и количества, а нужно умножение. Модель предложит исправление. Даже для такой маленькой правки важно увидеть её до записи: модель может заодно переименовать функцию, удалить проверку или "улучшить" что-то, о чём её не просили.

Функция `preview_change` подготовит предложение: сравнит старый и новый текст, соберёт список изменённых строк и запомнит контрольную сумму исходного файла. Сам файл останется прежним. Человек увидит конкретную правку и сможет её принять или отклонить, а контрольная сумма в следующем уроке подтвердит, что согласие относится именно к той версии файла, которую он видел.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-05-02-diff.zip?raw=true), распакуйте и откройте папку `lesson-05-02-diff` через **File -> Open**. Сегодняшнее задание - функция `preview_change` в файле `workspace.py`.

## Посмотрим на данные

Старая и новая строки расчёта:

```python
old_text = '    return price + quantity\n'
new_text = '    return price * quantity\n'
```

Программисты показывают такие изменения в виде diff: удаляемая строка отмечается знаком `-`, добавляемая - знаком `+`. Так выглядит любой обзор изменений в GitHub или GitLab. Для нашей правки diff будет таким:

```text
--- before/prices.py
+++ after/prices.py
@@ -1,2 +1,2 @@
 def total_price(price, quantity):
-    return price + quantity
+    return price * quantity
```

Вместе с diff сохраним хеш исходного файла - контрольную строку, которая вычисляется по его содержимому. Если в файле поменяется хоть один символ, хеш станет другим.

## Напишите сами

В `preview_change` путь уже проверен через `workspace_path`, а старый текст прочитан. Замените `raise NotImplementedError(...)` кодом ниже и заполните пропуски:

```python
    lines = difflib.unified_diff(
        old_text.splitlines(keepends=True),
        new_text.splitlines(keepends=True),
        fromfile='before/' + relative,
        tofile='after/' + relative,
    )
    before_hash = hashlib.sha256(path.read_bytes()).hexdigest()
    return {
        'path': relative,
        'before_hash': before_hash,
        'new_text': ...,
        'diff': ...,
    }
```

1. В `'new_text'` положите параметр `new_text`.
2. В `'diff'` - `''.join(lines)`: библиотека отдаёт строки сравнения по одной, а нам нужен единый текст. Разделитель пустой, потому что переводы строк уже сохранены благодаря `keepends=True`.

Сравнение строк готово в стандартной библиотеке `difflib`, придумывать его не нужно. `fromfile` и `tofile` - только подписи двух вариантов в diff, файлы они не создают. `hashlib.sha256(...).hexdigest()` вычисляет хеш по байтам исходного файла.

Функция возвращает подготовленное предложение: текст для показа человеку в `diff`, будущий код в `new_text` и `before_hash` для проверки перед записью. На диск при этом ничего не пишется.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. Модель получит учебный `prices.py` и предложит исправление, а ваша функция покажет разницу в Run. Ожидаем замену сложения умножением. Читайте фактический diff внимательно: модель может предложить лишние изменения или вовсе не исправить ошибку.

## Проверим функцию отдельно

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Ожидаем diff из раздела выше: строку с `-` для сложения и строку с `+` для умножения. Файл `workspace/prices.py` при этом не меняется, можно открыть его и убедиться. Для готовых проверок запустите `class LessonTests`.

## Что мы получили

Предложение агента отделено от изменения проекта: человек видит конкретную правку до того, как она попадёт в файл. Для руководителя это одна из главных точек контроля: агент предлагает, решение принимает человек.
