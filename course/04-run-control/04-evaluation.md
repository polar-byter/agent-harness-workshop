## Посмотрим на данные

В `cases` каждый словарь содержит имя сценария, задачу и ожидаемые `status` и `answer`. Функция `run` выполняет сценарий. Для учебных ответов проверим точное равенство; оценивать смысл свободного текста настоящей модели таким способом часто слишком строго.

```python
case = {'name': 'Обычный ответ', 'task': 'Найди Python',
        'expected_status': 'completed', 'expected_answer': 'Готово'}
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

Сравнение станет полезным, только если мы заранее договорились, что считать успехом. В каждом сценарии есть задача и ожидаемый ответ со статусом. Получим фактический результат через `run`, сравним оба поля и сохраним итог отдельно для каждого сценария.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть - вторую функцию с тем же именем создавать не нужно.

```python
def evaluate_cases(cases: list[dict], run) -> dict:
    results = []
    for case in cases:
        actual = run(case['task'])
        passed = ...
        results.append({'name': case['name'], 'passed': passed})
    passed_count = sum(item['passed'] for item in results)
    return {'passed': passed_count, 'total': len(results), 'results': results}
```

Сравните `actual["status"]` с `case["expected_status"]`, а `actual["answer"]` - с `case["expected_answer"]`. Между двумя сравнениями поставьте `and`: сценарий считается пройденным, когда совпали оба поля. Знак `==` сравнивает значения; одинарный `=` присваивает значение переменной.

`run(case["task"])` - такой же вызов переданной функции, как `send(messages)` во втором подпроекте. `len(results)` считает сценарии, а `sum(...)` складывает их логические результаты: `True` даёт единицу, `False` - ноль. Эта короткая запись уже приведена целиком. Для пустого набора оба счётчика получатся нулевыми.

## Найдём файл запуска и проверим результат

В левой панели **Project -> lesson-04-04-evaluation -> demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка «запустить проект» нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View -> Tool Windows -> Project**. Если Run скрыто - **View -> Tool Windows -> Run**.

До завершения функции появится сообщение «Допишите ... по подсказкам урока». После реализации ожидаем:

```text
passed: 2; total: 2; оба учебных сценария соответствуют ожиданиям.
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

## Когда будете готовы подключить модель

Пока `demo.py` использует подготовленный ответ или учебную функцию выбора действий. Это проверяет наш код, но не показывает качество настоящей модели. В этом же корне есть `demo_live.py` - отдельный сетевой запуск.

Для него нужны действующий доступ к API и выбранная доступная вам модель. В PyCharm откройте файл `demo_live.py`, создайте его конфигурацию через контекстное меню Run, затем откройте **Run -> Edit Configurations**. В настройке этого файла найдите **Environment variables** (при необходимости через **Modify options**) и задайте `OPENAI_API_KEY` и `OPENAI_MODEL`. Первое - ключ вашего аккаунта, второе - точное имя выбранной модели. Не вставляйте ключ в Python-файл или архив. Если доступа ещё нет, учебный маршрут можно продолжить с подготовленными ответами.

После настройки отдельно запустите `demo_live.py`. Он отправляет запрос в OpenAI Responses API через готовый `transport.py`; сетевой вызов расходует доступный бюджет API. Текст реального ответа заранее не фиксирован. Ошибку доступа или соединения разбираем отдельно: она не означает, что файл с заметками пуст. Другой сервис потребует своего адаптера. Эти архивы проверены локально; сетевые ответы при их подготовке не запрашивались.

Сейчас ваша работа - `evaluate_cases` в `control.py`; затем повторный запуск `demo.py`.
