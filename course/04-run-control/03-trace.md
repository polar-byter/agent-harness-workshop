# Урок 3. Сохраняем историю выполнения

Когда запуск останавливается по лимиту, одного слова «остановлен» мало. Хочется увидеть, что происходило до этого. Запишем события в файл, который можно открыть в редакторе и сопоставить с результатом.

## Посмотрим на данные

Мы уже дописывали отдельные результаты поиска в журнал. Теперь сохраняем полную историю одного запуска. Поэтому используем режим `w`: он заменяет содержимое выбранного файла. У каждого запуска должен быть свой путь, если предыдущую историю нужно сохранить.

```python
event = {'command': {'tool': 'read_notes'},
         'result': {'notes': ['Python lists']}}
json.dumps(event, ensure_ascii=False)
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

Мы уже сохраняли один результат поиска. Здесь задача похожая, только передана сразу история запуска — список словарей. Каркас превратил каждое событие в строку JSON; теперь запишем все строки в один файл, сохранив границы событий.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть — вторую функцию с тем же именем создавать не нужно.

```python
def save_events(path: Path, events: list[dict]) -> None:
    serialized = [json.dumps(event, ensure_ascii=False) for event in events]
    with path.open('w', encoding='utf-8') as stream:
        for text in serialized:
            stream.write(...)
```

Как и в первом журнале, в пропуске нужны `text` и перевод строки: `text + "\n"`. Отличается режим открытия. Здесь `w` выбран намеренно: файл хранит одну полную историю запуска и при повторном сохранении заменяется. Чтобы хранить несколько запусков, приложению нужно дать каждому свой путь.

Если событий нет, `serialized` будет пустым, цикл ничего не запишет, а открытие в режиме `w` оставит пустой файл. Поэтому отдельная ветка для пустого списка не требуется. Структуру каждого события не перестраиваем — иначе по журналу будет сложнее сопоставить команду с её результатом.

## Найдём файл запуска и проверим результат

В левой панели **Project → lesson-04-03-trace → demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка «запустить проект» нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View → Tool Windows → Project**. Если Run скрыто — **View → Tool Windows → Run**.

До завершения функции появится сообщение «Допишите … по подсказкам урока». После реализации ожидаем:

```text
{"command": {"tool": "read_notes"}, "result": {"notes": ["Python lists"]}}
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

Сейчас ваша работа — `save_events` в `control.py`; затем повторный запуск `demo.py`.
