> **Где мы находимся:** Наш помощник уже умеет читать регламент из файла на диске и отбирать нужные статьи по слову. 
> 
> Но пока результат его работы мелькает только на экране консоли PyCharm. Закрыли окно — и история исчезла. 
> 
> В этом уроке мы научим программу вести собственный нестираемый бортовой журнал (лог) в формате JSONL:
> 
> `файл регламента -> чтение -> поиск -> [наш журнал на диске]`

Представьте типичный разбор инцидента в службе поддержки:
Вчера в 14:30 клиент пожаловался, что бот дал ему неверный совет по возврату денег. Руководитель приходит к вам и спрашивает:
* *«Что именно искал бот в регламенте?»*
* *«Какие пункты правил он реально нашёл перед тем, как ответить клиенту?»*
* *«Был ли среди найденных пунктов тот самый регламент возвратов на карту?»*

Если программа не ведёт журнал, вы не сможете ответить ни на один из этих вопросов. Экран PyCharm давно закрыт, оперативная память очищена. Без логов вы остаётесь слепыми — ровно так, как это произошло в истории MWS из вводной статьи.

Именно поэтому любая серьёзная агентная система первым делом обзаводится **журналом аудита (Audit Log / Trace)**. Каждое действие программы должно оставлять чёткий след на диске.

## Что мы будем сохранять

После поиска у нас на руках есть два ключевых факта:
1. Поисковый запрос (например, `'возврат'`).
2. Список найденных строк регламента.

В Python такие связанные данные удобно объединять в **словарь (dict)**:

```python
result = {
    'query': 'возврат',
    'matches': [
        'Возврат товара возможен в течение 14 дней.'
    ]
}
```

Но словарь существует только в оперативной памяти компьютера. Чтобы сохранить его в текстовый файл на диск, его нужно перевести в общепринятый текстовый формат — **JSON** (JavaScript Object Notation):

```python
import json

text = json.dumps(result, ensure_ascii=False)
```

1. Функция `json.dumps(...)` превращает структуру данных Python (словарь, список, числа) в аккуратную компактную строку текста. Этот процесс называется **сериализацией**.
2. Параметр `ensure_ascii=False` обязателен для русскоязычных текстов! Если его забыть, Python заменит все русские буквы на служебные ASCII-коды вроде `\u0432\u043e\u0437\u0432\u0440\u0430\u0442`. С `ensure_ascii=False` русский текст сохранится нормальными читаемыми буквами.

Каждую операцию поиска мы будем записывать в файл **отдельной строкой**. Такой формат называется **JSONL** (JSON Lines — «JSON построчно»).

## Напишите код сами

Удалите строку `raise NotImplementedError(...)` и замените её безопасным блоком записи:

```python
    with path.open('a', encoding='utf-8') as stream:
        stream.write(...)
```

Заполните пропуск `...`:
* Нам нужно записать наш JSON и **обязательно добавить символ переноса строки**: `text + '\n'`

### Разберём каждую деталь этой конструкции:
* `with path.open(...) as stream:` — так называемый **контекстный менеджер**. Он открывает файл под временным именем `stream` («поток данных»). Главная суперсила конструкции `with`: как только блок кода закончится (или если вдруг произойдёт сбой), Python **гарантированно закроет файл** и сохранит все данные на диск. Никаких утечек ресурсов!
* Режим `'a'` (от английского *append* — «дописать»): в отличие от обычного режима записи `'w'`, который при открытии стирает файл начисто, режим `'a'` открывает файл и ставит курсор в самый конец. Если файла ещё нет, Python создаст его автоматически.
* `encoding='utf-8'` — сохраняем русский текст в универсальной кодировке.
* `text + '\n'` — символ `\n` переносит курсор на следующую строку. Если его не добавить, следующая запись приклеится вплотную к концу предыдущей, и наш JSONL превратится в кашу.
* Обратите внимание: функция ничего не возвращает (`-> None`). Её результат — реальное физическое изменение файла на диске.

### Почему именно JSONL, а не обычный JSON или база данных?

Новички часто спрашивают: *«Почему не сохранить просто один большой список в файле `runs.json`?»*

Казалось бы, красивый JSON выглядит понятнее:
```json
[
  {"query": "возврат", "matches": [...]},
  {"query": "доставка", "matches": [...]}
]
```

Но у классического JSON есть фатальный недостаток в боевых системах:
1. **Катастрофа при аварии:** Чтобы добавить 1001-ю запись в обычный `runs.json`, программа должна:
   * Прочитать весь гигантский файл целиком в оперативную память.
   * Распарсить его.
   * Добавить новый элемент в список.
   * Перезаписать весь файл на диске с нуля.
   Если в момент перезаписи моргнёт свет или упадёт сервер — файл повредится целиком (оборвётся закрывающая скобка `]`), и вы потеряете всю историю.
2. **Суперсила JSONL (Append-Only):**
   В формате JSON Lines каждая строка — это полностью самостоятельный, валидный JSON. 
   * Добавление новой записи занимает миллисекунды: программа просто делает мгновенный append в конец файла.
   * Даже если процесс аварийно завершится, все предыдущие строки гарантированно останутся целыми и невредимыми.
   * Файл можно читать построчно потоком, не загружая гигабайты логов в оперативную память.

Именно поэтому **OpenAI, Anthropic, LangSmith, Datadog** и все ведущие агентные платформы сохраняют датасеты, трейсы и логи именно в формате `.jsonl`.

### Как устроен скрипт запуска `demo.py`

Посмотрим, как устроен `demo.py` в этом уроке:

```python
from pathlib import Path
from notes import read_notes, find_notes
from journal import write_result

ROOT = Path(__file__).resolve().parent

def main():
    notes_path = ROOT / 'data' / 'notes.txt'
    journal_path = ROOT / 'runs.jsonl'
    
    # 1. Читаем регламент:
    notes = read_notes(notes_path)
    
    # 2. Ищем нужный пункт:
    query = 'возврат'
    matches = find_notes(notes, query)
    
    # 3. Собираем отчёт:
    result = {'query': query, 'matches': matches}
    
    # 4. Записываем в журнал:
    write_result(journal_path, result)
    print(f"Записано в журнал: {result}")

if __name__ == '__main__':
    main()
```

Посмотрите, как красиво собирается наша мозаика:
* `notes.py` отвечает только за обработку текста.
* `journal.py` отвечает только за сохранение на диск.
* `demo.py` соединяет их в цепочку.

<details>
<summary>Бонус для любознательных: как быстро прочитать файл JSONL в Python</summary>

Чтобы считать записи из файла JSONL обратно в Python, достаточно прочитать файл построчно и применить `json.loads` (load string) к каждой строке:

```python
import json
from pathlib import Path

journal_path = Path('runs.jsonl')

with journal_path.open('r', encoding='utf-8') as stream:
    for line in stream:
        if line.strip():
            record = json.loads(line)
            print(f"Запрос: {record['query']} -> Найдено: {len(record['matches'])} пунктов")
```

Каждая строчка мгновенно превращается обратно в обычный словарь Python!

</details>
