# Подсказки к текущему заданию

> **Где мы.** У помощника есть агентный цикл: модель выбирает действие, программа выполняет, результат возвращается модели. Начинаем раздел о том, как управлять таким циклом. Первое - вовремя его остановить.
> `модель -> действие -> результат -> [проверка лимита] -> модель ...`

Представим, что агент уже прочитал регламент, но снова и снова просит прочитать его ещё раз. Каждое такое действие разрешено, поэтому `dispatch_tool` его пропустит. А цикл тем временем крутится, тратит время и, у облачного сервиса, деньги. Руководителю, который отвечает за бюджет пилота, такой агент не понравится.

Правило в промпте "закончи, когда найдёшь ответ" не спасёт: решение об остановке нельзя целиком оставлять модели. Поэтому программа будет сама считать обращения к модели и вызовы инструментов и останавливать работу, как только один из счётчиков дойдёт до лимита. Считаем именно действия; стоимость в токенах - отдельная тема, её мы смотрели в практикуме со статистикой.

Откройте `control.py` -> функция `check_budget`.

## Напишите сами

В `check_budget` пока только прочитаны два счётчика. Замените строку `raise NotImplementedError(...)` кодом ниже и заполните пропуски:

```python
    for name in ('steps', 'tool_calls'):
        if type(state.get(name)) is not int or state[name] < 0:
            raise ValueError('Неверный счётчик: ' + name)
        if type(limits.get(name)) is not int or limits[name] < 1:
            raise ValueError('Неверный лимит: ' + name)
    steps_available = ...
    tools_available = ...
    return steps_available and tools_available
```

1. В `steps_available` запишите сравнение `state['steps'] < limits['steps']`.
2. В `tools_available` - такое же сравнение для ключа `'tool_calls'`.

`and` вернёт `True`, только если истинны оба сравнения. Если счётчик уже равен лимиту, следующего шага не будет.

Цикл в начале проверяет, что в словарях лежат целые числа. Запись `type(value) is int` строже, чем кажется: в Python `True` ведёт себя как число `1`, и без такой проверки счётчик мог бы оказаться логическим значением.

Функция ничего не увеличивает и сама шаг не запускает: она только отвечает управляющему коду, можно ли продолжать.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. Модель выбирает действия, а ваша функция перед каждым шагом проверяет счётчики. В `demo.py` заданы лимиты: четыре обращения и три вызова инструментов. В Run появятся команды, результаты и ответ модели либо сообщение о достигнутом лимите.

## Проверим функцию отдельно

Откройте `demo_check.py` и выберите **Run 'demo_check'**. На контрольных данных `steps=2`, `tool_calls=1` и лимитах `4` и `2` ожидаем `True`. Для готовых проверок запустите `class LessonTests` в `tests/test_lesson.py`.

## Попробуйте сломать

В `demo.py` поменяйте лимит инструментов с `3` на `1` и запустите снова. Если модель захочет больше одного действия, программа остановит её после первого и сообщит о лимите. Обратите внимание, что это решение принимает код, а не модель. Верните `3`.
