# Урок 2. Выбираем историю для следующего шага

[Открыть исходники этого урока](../../exercises/lesson-04-02-context/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-04-02-context/TASK.md)

> **Где мы.** Агентный цикл ограничен по числу шагов. Теперь займёмся тем, что модель получает на каждом шаге: всю накопленную историю или только её часть.
> `история -> [выбор части] -> модель -> действие -> история ...`

После нескольких действий у помощника накапливается история: запросы к инструментам и их результаты. Если на каждом шаге отправлять модели всё, запрос будет расти, а с ним время и стоимость. Если отправлять слишком мало, модель потеряет нужные сведения, например пункт, который нашла три шага назад, и попросит поиск заново.

Попробуем простое правило: исходную задачу передаём всегда, а из истории - только последние события. Функция `select_context` подготовит такой набор и при этом не тронет полную историю, которую хранит программа. Когда агент начинает повторяться или забывает, что уже сделал, причину часто ищут именно здесь: в том, что ему передали.

## Посмотрим на данные

Возьмём историю из трёх событий и оставим два последних. Чтобы был виден сам отбор, обозначим события номерами:

```python
events = [{'step': 1}, {'step': 2}, {'step': 3}]
events[-2:]   # [{'step': 2}, {'step': 3}]
```

В настоящей истории на месте каждого элемента - словарь с командой и результатом; событие сохраняется или исключается целиком. Сколько событий оставить, задаёт параметр `max_events`, а задачу `task` передаём в любом случае. Всё, что не вошло в выбранную часть, модель в этом обращении не увидит.

## Напишите сами

В `select_context` уже проверен `max_events` и создан словарь `context` с задачей и пустым списком событий. Замените `raise NotImplementedError(...)` кодом ниже и заполните пропуск:

```python
    if max_events > 0:
        context['events'] = ...
    return context
```

В пропуск подставьте срез `events[-max_events:]`. Квадратные скобки с двоеточием создают новый список из части старого: `-2:` означает "два последних элемента". Сам `events` от этого не меняется.

Условие `max_events > 0` нужно из-за особенности Python: `events[-0:]` то же самое, что `events[0:]`, то есть вся история. Без проверки нулевой лимит отправил бы модели всё.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. Перед каждым обращением к модели программа вызывает вашу функцию. В Run появятся статус, ответ и история. Посмотрите, какие события остаются при выбранном `max_events`: исключённые в этом запросе модель не видела.

## Проверим функцию отдельно

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Ожидаем:

Задача на месте, из истории взяты два последних события. Для готовых проверок запустите `class LessonTests` в `tests/test_lesson.py`.

## Попробуйте сломать

В `demo_check.py` поменяйте последний аргумент вызова с `2` на `0`. Ожидаем пустой список событий. Теперь временно уберите из своей функции условие `if max_events > 0:` (оставив присваивание без отступа) и запустите снова: вернётся вся история. Восстановите условие.

## Что мы получили

Программа сама решает, какие сведения увидит модель на следующем шаге. Это часть работы, которую называют **управлением контекстом**, по-английски context engineering: какие инструкции, источники и какую историю положить в очередной запрос. Правило "последние события" самое простое и важность сведений по смыслу не учитывает. Зато теперь видно место, где принимается это решение. Подробнее - в [памятке терминов](../terms.md#%D1%83%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D0%B5-%D0%BA%D0%BE%D0%BD%D1%82%D0%B5%D0%BA%D1%81%D1%82%D0%BE%D0%BC).
