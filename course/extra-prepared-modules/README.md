# Как разобраться в готовых модулях

> **Где мы.** В основных уроках раздела 3 модель просит программу выполнить поиск, а программа решает, разрешено ли это. Часть этого обмена была готова заранее: модули `decisions.py` и `transport.py`. Этот необязательный учебник - для тех, кто хочет написать их сам.

Вспомним задачу: клиент спрашивает о возврате, и помощник должен найти нужные пункты регламента. Модель возвращает просьбу "выполни поиск с запросом возврат", но читает файл и ищет программа. Чтобы такой обмен состоялся, программа сначала объясняет модели, какие действия ей доступны и в каком виде их просить, а потом разбирает текст её ответа. При следующем обращении она передаёт результаты уже выполненных действий, иначе модель не узнает, что нашлось.

В основных каркасах этим занимаются функция `decide_live` из `decisions.py` и модуль `transport.py`, отвечающий за соединение с Ollama или облачным сервисом. Здесь мы напишем их части по отдельности, а затем соберём работающую `decide_live`.

## Вспомним путь от просьбы до ответа

| Что происходит | Кто делает |
|---|---|
| Получает задачу "найди пункты о возврате", правила и результаты прежних действий | Модель |
| Возвращает текст команды с названием поиска и запросом "возврат" | Модель |
| Разбирает команду, проверяет, разрешено ли действие, выполняет поиск | Программа |
| Передаёт найденные пункты вместе с задачей при следующем обращении | Программа |
| Отвечает клиенту по найденным пунктам | Модель |

Этот учебник посвящён первым двум строкам и переходу между ними: как программа готовит сообщения, отправляет их и превращает ответ модели в данные. Выполнение команды остаётся в основном проекте.

## Когда открывать эти уроки

Начать можно после [подключения модели](../02-note-assistant/04-connect.md). Особенно удобно вернуться сюда, когда в [уроке с инструментами](../03-tool-agent/01-tools.md) впервые встретится `decide_live`. Разбираться заранее в агентном цикле не нужно: как он связан с нашей функцией, посмотрим в конце.

## Четыре шага

| Урок | Что напишем | Где |
|---|---|---|
| [Как подготовить задачу для модели](01-messages.md) | `build_decision_messages` | `decisions.py` |
| [Как получить команду из текста](02-command.md) | `parse_decision` | `decisions.py` |
| [Как Python отправляет запрос](03-request.md) | `request_json` | `transport.py` |
| [Собираем decide_live из знакомых функций](04-decision.md) | `decide_live` | `decisions.py` |

У каждого урока свой архив, предыдущие части в нём уже готовы. В первых двух модель не нужна: мы смотрим на данные до отправки и после получения ответа. В третьем и четвёртом сначала проверим код без сети, а затем сделаем настоящий запрос через сохранённое подключение.

## Как это связано с основным каркасом

`decisions.py` превращает задачу и историю действий в сообщения, получает ответ через `send_live` и разбирает текст команды. `transport.py` выбирает адрес сервиса, отправляет запрос и приводит ответ к общему формату курса. Выполняет команду `dispatch_tool`, а повторяет шаги `run_agent`.

В этом учебнике мы разделим исходную `decide_live` на несколько небольших функций, чтобы написать и проверить каждую отдельно. Файлы основных уроков менять не придётся.

Если сейчас хочется просто прочитать готовый код, начните со статьи [как устроена send_live](../02-note-assistant/extra-send-live.md). Если хочется написать самому - с первого урока в таблице. Вернуться в [основной маршрут](../README.md).
