# Сопровождение курса

После урока 2.4 основной запуск использует модель, а `demo_check.py` остаётся проверкой без неё. В конфигурации нового урока `ready: true` означает готовый код и задачу настройки вместо реализации заглушки. Общие готовые модули хранятся в `tools/model_runtime`; проверка курса сверяет их с копиями в каркасах. При изменении модулей сначала обновите их в канонических ZIP Obsidian, затем выполните экспорт. Не меняйте только распакованную копию. Исторический `build_full_course.py` в мастерской ещё содержит старую схему запуска: не используйте его для перезаписи актуальных архивов без переноса новой схемы.

Читательский вход - корневой README и `course/README.md`. В этой папке описаны сборка и проверки курса.

- `export-manifest.json` - состав последнего экспорта с контрольными суммами файлов.
- `../tools/course-map.json` - соответствие заметок Obsidian страницам GitHub, архивам и исходникам.

## Обновить материалы из Obsidian

В корне репозитория выполните:

```powershell
python tools/export_obsidian.py --vault 'путь-к-корню-хранилища'
python tools/check_course.py
```

Команда читает только заметки читательского курса и материалы, на которые они ссылаются. Рабочие итерации, история чата и соседние разделы хранилища сюда не копируются. Относительные ссылки, изображения и раскрывающиеся блоки преобразуются для GitHub.

Если экспортируемый файл изменён вручную в репозитории, экспорт остановится до записи. Сначала сравните изменения и перенесите нужное в исходный материал; не стирайте решение ученика ради пересборки. `README.md` в корне и этот журнал редактируются отдельно и не генерируются из Obsidian.

## Что проверяется

Дополнительный раздел `course/extra-prepared-modules` разбирает готовые `decisions.py` и `transport.py` в четырёх независимых упражнениях. Первые два запускают только подготовку и разбор данных, в третьем и четвёртом `demo.py` делает настоящий запрос после реализации функции. `demo_check.py` всегда работает без сети. Поле `runtime_modules` в карте курса перечисляет готовые модули, которые должны побайтово совпадать с `tools/model_runtime`: пустой список применяется к первым двум шагам, а урок написания `request_json` сверяет только `configure_model.py`, поскольку сетевую функцию в `transport.py` пишет читатель. Для остальных уроков по умолчанию сверяются оба модуля.

`tools/check_course.py` проверяет локальные ссылки, синтаксис Python, целостность архивов, совпадение кода архива с папкой упражнения и ожидаемое поведение незавершённых демонстраций. Проверка не вызывает API и не оценивает ответы модели. Успех сборки не означает, что все учебные функции реализованы.

Проверки решений расположены в `exercises/lesson-.../tests/test_lesson.py`. Их запускает читатель после выполнения соответствующего задания. До этого они закономерно не проходят.
