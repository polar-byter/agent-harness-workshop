# Урок 2. Прочитаем регламент из файла

[Открыть исходники этого урока](../../exercises/lesson-01-02-read/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-01-02-read/TASK.md)

> **Где мы.** Собираем помощника, который отвечает по регламенту. В прошлом уроке он научился искать пункты по слову, но сами пункты мы записали прямо в коде. Теперь возьмём их из файла.
> `файл регламента -> [чтение] -> поиск -> модель -> ответ`

В рабочих системах регламент хранится отдельно от программы: в файле, в базе знаний, в Confluence. Прежде чем искать, помощник должен документ прочитать, и на этом шаге тоже случаются сбои.

Допустим, помощник ответил клиенту: "Сведений о возврате не найдено". Причин может быть две. Регламент прочитан, но пункта о возврате в нём нет - тогда документ должен дополнить его владелец. Или файл не открылся: его переложили в другую папку, переименовали, у программы нет доступа - тогда разбирается администратор. Если программа сообщает об обоих случаях одной фразой, вопрос уйдёт не тому человеку. Поэтому чтение напишем так, чтобы эти случаи различались.

Перед вторым пунктом стоят лишние пробелы, после него пустая строка - после нескольких правок файл часто так и выглядит. Поиску же нужен аккуратный список, по одному пункту на элемент:

```python

 'Доставка по городу занимает 1 день.',
 'ВОЗВРАТ денег производится на карту покупателя.',

 'Обмен товара оформляется в пункте выдачи.',
 'Претензию рассматривают 10 рабочих дней.']
```

Такой список получала функция `find_notes` в прошлом уроке. Наша задача - сделать его из файла.

## Шаг 1. Прочитаем файл целиком

Путь к файлу в Python удобно задавать объектом `Path`, а содержимое читать его методом `read_text`:

```python
path = Path('data/notes.txt')
text = path.read_text(encoding='utf-8')
```

Первая строка только указывает, где лежит файл, а текст появляется после вызова `read_text`. Параметр `encoding='utf-8'` задаёт кодировку: без него на Windows русские буквы могут прочитаться неправильно. В нашей функции путь создавать не придётся: его передаст аргументом `demo_read.py`.

В `text` теперь одна длинная строка со всем регламентом, переходы между строками файла в ней обозначены символом `\n`.

## Шаг 2. Разрежем текст на строки

Метод `splitlines()` делит текст по переходам строк и возвращает список. Покажу на первых трёх строках файла:

```python
lines = text.splitlines()
# ['Возврат товара возможен в течение 14 дней.',
#  '  Доставка по городу занимает 1 день.',
#  '',
#  'ВОЗВРАТ денег производится на карту покупателя.',
#  ...]
```

Вот и ответ на вопрос выше: элементов семь, а не шесть. Пустая строка между пунктами превратилась в пустой элемент `''`, а пробелы перед словом "Доставка" никуда не делись. Если отдать такой список поиску, он будет перебирать пустой элемент, а пробелы попадут в ответ модели.

## Шаг 3. Очистим каждую строку

Пробелы по краям уберём знакомым методом `strip()`, а в список оставим только строки, в которых после этого что-то осталось. Проходим по строкам циклом, как в прошлом уроке:

```python
cleaned_notes = []
for line in lines:
    cleaned_line = line.strip()
    if cleaned_line:
        cleaned_notes.append(cleaned_line)
```

Условие `if cleaned_line` выполняется только для непустой строки: пустую Python считает ложным значением. Пробелы между словами `strip()` не трогает, только по краям.

## Напишите сами

Откройте `notes.py` и найдите функцию `read_notes`. Чтение файла и деление на строки в ней уже написаны, список `cleaned_notes` создан. Замените строку `raise NotImplementedError(...)` циклом и заполните пропуски:

```python
    for line in lines:
        cleaned_line = ...
        if ...:
            cleaned_notes.append(...)
    return cleaned_notes
```

1. В `cleaned_line` запишите очищенную строку: `line.strip()`.
2. В условие - то, при котором строку стоит сохранить: сама `cleaned_line`.
3. В `append` передайте `cleaned_line`, а не исходную `line` с пробелами.

Строка `return cleaned_notes` стоит после цикла и отдаёт готовый список тому, кто вызвал функцию. Если в файле совсем нет текста, цикл не выполнится ни разу и функция вернёт пустой список.

## Попробуйте сломать

1. **Пустой регламент.** Сотрите содержимое `data/notes.txt` и сохраните файл. После запуска `demo_read.py` функция вернёт пустой список `[]`: файл прочитан, пунктов в нём нет.
2. **Файла нет.** Верните текст и переименуйте файл, например в `notes_old.txt`. Теперь программа остановится с ошибкой `FileNotFoundError`, и в сообщении будет имя файла, который она не нашла.

Вернёмся к примеру из начала урока. Пустой список означает, что дополнять нужно сам регламент. `FileNotFoundError` означает, что до документа программа не добралась. Поэтому ошибку мы не перехватываем и не превращаем в пустой список: иначе помощник ответил бы "сведений не найдено", и никто бы не узнал, что документ он даже не открывал.
