## Посмотрим на данные

В `state` лежат уже выполненные `steps` и `tool_calls`, в `limits` — предельные значения. Пока оба счётчика меньше лимитов, можно продолжать. Лимит вызовов инструмента в этой учебной версии также завершает весь запуск: отдельный последний запрос к модели после него не предусмотрен.

```python
state = {'steps': 2, 'tool_calls': 1}
limits = {'steps': 4, 'tool_calls': 2}
state['steps'] < limits['steps']  # True
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

У нас два независимых ограничения: сколько шагов уже сделано и сколько раз вызваны инструменты. Продолжать можно, только пока не исчерпан ни один лимит. Например, при двух выполненных шагах из четырёх и одном вызове из двух ещё остаётся возможность действовать.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть — вторую функцию с тем же именем создавать не нужно.

```python
def check_budget(state: dict, limits: dict) -> bool:
    for name in ('steps', 'tool_calls'):
        if type(state.get(name)) is not int or state[name] < 0:
            raise ValueError('Неверный счётчик: ' + name)
        if type(limits.get(name)) is not int or limits[name] < 1:
            raise ValueError('Неверный лимит: ' + name)
    steps_available = ...
    tools_available = ...
    return steps_available and tools_available
```

Первое сравнение — `state["steps"] < limits["steps"]`, второе такое же для ключа `"tool_calls"`. Оператор `and` вернёт `True` только тогда, когда истинны оба сравнения. Если счётчик уже равен лимиту, следующего действия не разрешаем.

Начальная проверка данных приведена целиком: `type(value) is int` требует именно целое число. Это полезно потому, что в Python `True` также ведёт себя как число `1`; в счётчиках такое значение принимать не будем. В каркасе пока лишь прочитаны два счётчика — перед итоговыми сравнениями добавьте показанную проверку.

## Найдём файл запуска и проверим результат

В левой панели **Project → lesson-04-01-budget → demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка «запустить проект» нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View → Tool Windows → Project**. Если Run скрыто — **View → Tool Windows → Run**.

До завершения функции появится сообщение «Допишите … по подсказкам урока». После реализации ожидаем:

```text
True
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

Сейчас ваша работа — `check_budget` в `control.py`; затем повторный запуск `demo.py`.
