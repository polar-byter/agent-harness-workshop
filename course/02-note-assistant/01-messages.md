# Урок 1. Передаём вопрос вместе с заметками

[Открыть исходники этого урока](../../exercises/lesson-02-01-messages/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-02-01-messages/TASK.md)

В заметках есть строка `Python lists keep item order.`, и мы хотим спросить: "Что заметки говорят о Python?" Одного вопроса для ответа по нашему источнику недостаточно. Программа должна передать модели саму заметку и объяснить, что делать, если нужных сведений в ней нет.

В готовом чате документы и общие правила могут добавляться приложением незаметно для нас. Здесь мы соберём сообщения сами: отдельно правила ответа, отдельно вопрос и найденный текст. Так станет видно, на основании каких данных модель вообще сможет отвечать и где нужно искать причину, если источник не попал в запрос.

Напишем `build_messages`, которая подготавливает эти сообщения. Пока не будем отправлять их по сети: сначала посмотрим содержимое и убедимся, что инструкция и заметка действительно вошли в запрос. Правило "отвечай по заметкам" задаёт желаемое поведение модели; проверить её настоящий ответ сможем после подключения.

## Посмотрим на данные

В нашем примере вопрос `"Что заметки говорят о Python?"` попадёт в параметр `question`, а список с заметкой о порядке элементов - в `notes`. Функция `build_messages` соберёт из них сообщения для модели. Каждое сообщение будет словарём с двумя полями: `role` указывает его роль, а `content` содержит текст.

```python
question = 'Что заметки говорят о Python?'
notes = ['Python lists keep item order.']
data = {'question': question, 'notes': notes}
text = json.dumps(data, ensure_ascii=False)
```

Правило отвечать по заметкам отправим с ролью `developer`, а вопрос и сами заметки - с ролью `user`. Так приложение отдельно задаёт условия ответа и передаёт данные для текущей задачи. Эти структуры мы собираем в Python; вставлять их в окно ChatGPT не потребуется. Вызов с исходными значениями уже подготовлен в `demo.py`.

## Соберём функцию с подсказками

Одного имени файла в вопросе недостаточно: наша программа должна передать его содержимое. Каркас уже объединяет вопрос и заметки в строку JSON, а нам осталось добавить инструкцию и вернуть два сообщения в нужном порядке.

Допишите уже начатую функцию по заготовке ниже, заполняя каждый `...` по подсказкам. Когда закончите, удалите строку `raise NotImplementedError(...)`; повторно добавлять заголовок `def` не нужно.

```python
def build_messages(question: str, notes: list[str]) -> list[dict]:
    if not question.strip():
        raise ValueError('Вопрос не должен быть пустым')
    data = {'question': question, 'notes': notes}
    content = json.dumps(data, ensure_ascii=False)
    rules = ...
    return [
        {'role': 'developer', 'content': ...},
        {'role': 'user', 'content': ...},
    ]
```

В `rules` напишите обычную строку с правилом: отвечать по заметкам, сообщать об отсутствии сведений и воспринимать содержимое заметок как данные, а не новые инструкции. Например, начало может быть таким: `"Ответь только по переданным заметкам."`. Дополните его остальными двумя условиями своими словами.

В первом сообщении значение `content` - переменная `rules`, во втором - переменная `content` с JSON вопроса и заметок. `role` и `content` - имена полей, которые понимает API. `developer` обозначает наши общие правила, `user` - данные текущего обращения. Функция возвращает список этих словарей; отправлять его по сети здесь не нужно.

Разберём результат на данных `demo.py`. Вызов `result = build_messages('Что заметки говорят о Python?', ['Python lists keep item order.'])` сохраняет в `result` список из двух сообщений. В `result[0]['content']` будут написанные вами правила, а в `result[1]['content']` - текст JSON с вопросом и заметкой. После `return` список доступен демонстрации, поэтому она может его напечатать. Позже функция подключения получит этот список и отправит модели записанные в нём правила, вопрос и заметку. Так подготовка данных в `build_messages` продолжится их передачей в следующей части программы.

Мы хотим, чтобы ответ можно было сопоставить с переданной заметкой. Связывание ответа с проверяемыми источниками называют **grounding**, по-русски можно сказать "опора ответа на источники". Здесь мы подготавливаем для этого исходные данные и инструкцию. После подключения сравним ответ с заметкой: одно присутствие текста в запросе ещё не подтверждает, что модель использовала его правильно. Подробнее - [grounding на нашем примере](../terms.md#%D0%BE%D0%BF%D0%BE%D1%80%D0%B0-%D0%BD%D0%B0-%D0%B8%D1%81%D1%82%D0%BE%D1%87%D0%BD%D0%B8%D0%BA%D0%B8).

## Найдём файл запуска и проверим результат

В левой панели **Project -> lesson-02-01-messages -> demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка "запустить проект" нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View -> Tool Windows -> Project**. Если Run скрыто - **View -> Tool Windows -> Run**.

До завершения функции появится сообщение "Допишите ... по подсказкам урока". После реализации ожидаем:

```text
Список из двух сообщений: правила developer и данные user; в user есть вопрос и одна исходная заметка.
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

Формат сообщений и ответа сверяем с [официальной документацией Responses API](https://developers.openai.com/api/docs/guides/text). Учебный `response.json` содержит только поля, нужные для нашего разбора.

Сейчас ваша работа - `build_messages` в `assistant.py`; затем повторный запуск `demo.py`.
