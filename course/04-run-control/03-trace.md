# Урок 3. Сохраняем историю выполнения

[Открыть исходники этого урока](../../exercises/lesson-04-03-trace/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-04-03-trace/TASK.md)

> **Где мы.** Агент работает в ограниченном цикле, и программа решает, какую часть истории показать модели. Теперь сохраним полную историю в файл, чтобы разбирать запуски после их окончания.
> `цикл агента -> история -> [файл events.jsonl]`

Помощник остановился, а по итоговому сообщению непонятно, что было до этого. Не нашёл нужный пункт? Несколько раз повторил поиск? Выбрал не тот инструмент? Чтобы ответить, нужно сохранить команды и результаты в том порядке, в котором они появлялись. Без такого журнала разбор жалобы клиента сводится к догадкам. С журналом можно показать коллеге или подрядчику конкретную строку: вот что агент запросил, вот что получил.

Функция `save_events` запишет историю в файл, по одному событию на строку JSON. Сохранять будем полную историю, даже если модель на каждом шаге видела только её часть: так видно и то, что было у программы, и то, что дошло до модели.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-04-03-trace.zip?raw=true), распакуйте и откройте папку `lesson-04-03-trace` через **File -> Open**. Сегодняшнее задание - функция `save_events` в файле `control.py`.

## Посмотрим на данные

В функцию придёт список событий завершённого запуска. Одно событие - словарь с командой и результатом. Вот агент попросил прочитать регламент и получил один пункт:

```python
event = {'command': {'tool': 'read_notes'},
         'result': {'notes': ['Возврат товара возможен в течение 14 дней.']}}
json.dumps(event, ensure_ascii=False)
```

Каждое событие запишем отдельной строкой JSON, как результаты поиска в уроке 1.3. Отличие одно: здесь файл хранит историю одного запуска, поэтому откроем его в режиме `'w'` и прежнее содержимое заменим. Если нужно хранить несколько запусков, каждому даётся свой файл.

## Напишите сами

В `save_events` каждое событие уже превращено в строку JSON: готовый список лежит в `serialized`. Замените `raise NotImplementedError(...)` кодом ниже и заполните пропуск:

```python
    with path.open('w', encoding='utf-8') as stream:
        for text in serialized:
            stream.write(...)
```

В пропуск, как и в первом журнале, передайте `text + '\n'`. Если событий нет, цикл ничего не запишет, а файл останется пустым: отдельная проверка для этого случая не нужна.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. После работы агента программа передаст историю в вашу функцию, а в Run появится итог и сообщение о файле `events.jsonl`. Откройте этот файл в корне проекта и сопоставьте команды с результатами. Это история вашего запуска, поэтому строки в ней будут свои.

## Попробуйте разобрать запуск

Запустите `demo.py` ещё раз и откройте свежий `events.jsonl`. Ответьте по нему на три вопроса: какой инструмент модель запросила первым, с каким запросом и сколько пунктов ей вернулись. Если модель отвечала клиенту, сверьте ответ с пунктами из журнала. По такому журналу и разбирают случаи вроде истории MWS.

## Что мы получили

После каждого запуска остаётся журнал действий агента. Восстановление пути выполнения по таким записям называют **трассировкой**, по-английски tracing. Наш журнал - самый простой её вариант: последовательность команд и результатов. В промышленных системах вроде OpenTelemetry записи ещё связываются между собой идентификаторами и хранят длительность каждой операции. Подробнее - в [памятке терминов](../terms.md#%D1%82%D1%80%D0%B0%D1%81%D1%81%D0%B8%D1%80%D0%BE%D0%B2%D0%BA%D0%B0).
