# Урок 3. Соединяем запрос и ответ

[Открыть исходники этого урока](../../exercises/lesson-02-03-answer/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-02-03-answer/TASK.md)

> **Где мы.** Есть функция, которая собирает сообщения, и функция, которая достаёт текст из ответа. Между ними не хватает звена: отправить сообщения и получить ответ. Соединим всё в одну функцию.
> `вопрос + пункты -> сообщения -> [отправка] -> ответ -> текст`

Отправлять сообщения можно по-разному: в облачный сервис, в Ollama на своём компьютере или, для проверки, вообще никуда, а просто прочитать готовый ответ из файла. Если зашить один способ внутрь функции, при каждой смене подключения придётся её переписывать, и легко сломать то, что уже работало. Поэтому способ отправки передадим в функцию отдельным параметром `send`. Сегодня это будет чтение готового ответа из файла, а в следующем уроке - настоящая модель, и сама функция при этом не изменится.

Такое разделение пригодится и при разборе ошибок. Если ответ неверный, можно отдельно проверить, что ушло в запрос, дошёл ли он до сервиса и правильно ли разобран ответ.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-02-03-answer.zip?raw=true), распакуйте и откройте папку `lesson-02-03-answer` через **File -> Open**. Сегодняшнее задание - функция `answer_question` в файле `assistant.py`.

## Посмотрим на данные

В `demo.py` функция вызывается так:

```python
result = answer_question(
    'Сколько дней есть на возврат товара?',
    ['Возврат товара возможен в течение 14 дней.'],
    send_fixture,
)
```

Первые два аргумента знакомы: вопрос и список пунктов. Третий, `send_fixture`, - это готовая функция из файла `transport.py`. Она читает `data/response.json` и возвращает словарь с ответом. Обратите внимание: `send_fixture` написана без скобок. Так мы передаём саму функцию, а не результат её вызова. Внутри `answer_question` она будет доступна под именем `send`, и вызов `send(messages)` выполнит именно её.

## Напишите сами

В `answer_question` уже есть проверка на пустой список и подготовка сообщений. Замените `raise NotImplementedError(...)` тремя строками и заполните пропуски:

```python
    response = ...
    answer = ...
    return answer
```

1. В `response` запишите результат вызова `send(messages)`.
2. В `answer` - результат `extract_answer(response)`.

Если пунктов не нашлось, функция ещё в начале вернёт "Подходящих заметок нет." и к модели обращаться не станет: отвечать ей было бы не по чему.

## Запустим

Откройте `demo.py` и выберите **Run 'demo'**. В окне Run должно появиться:

```text
Вернуть товар можно в течение 14 дней.
```

Проследим путь данных. `build_messages` собрала правило, вопрос и пункт. `send(messages)` вызвала `send_fixture`, и та вернула словарь из файла. `extract_answer` достала из словаря строку, а `return` передал её в `demo.py`, где она и напечатана.

## Попробуйте сломать

Замените в `demo.py` вопрос на `'Сколько стоит доставка за город?'` и запустите снова. Ответ останется прежним: про 14 дней. Модели здесь нет, `send_fixture` всегда возвращает один и тот же записанный ответ. Именно поэтому такой запуск годится для проверки соединения функций, но ничего не говорит о том, как ответит настоящая модель. Верните исходный вопрос.

## Что мы получили

Путь от вопроса до текста ответа собран и проверен на известных данных. В следующем уроке вместо `send_fixture` передадим `send_live`, и ответ будет давать настоящая модель. Для готовых проверок откройте `tests/test_lesson.py` и запустите `class LessonTests`.
