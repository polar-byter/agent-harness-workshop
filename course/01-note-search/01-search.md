## Шаг 1. Очистим запрос от лишнего мусора

Человек может случайно ввести слово с пробелами по краям или набрать его большими буквами: `'  Возврат  '`. 

Если сравнивать строку напрямую, поиск сломается: пробелы помешают совпадению, а `'возврат'` и `'Возврат'` в Python считаются совершенно разными строками.

Поэтому первым делом приведём запрос к предсказуемому каноническому виду:
1. Отрежем пробелы по краям с помощью `.strip()`.
2. Переведём все буквы в нижний регистр с помощью `.casefold()`.

```python
query = '  Возврат  '
query = query.strip().casefold()
print(query)   # Выведет: 'возврат'
```

*Почему именно `casefold()`, а не привычный `lower()`?* `casefold()` работает глубже и корректнее с международными алфавитами и сложными символами. С кириллицей он справляется идеально: `'ВОЗВРАТ'.casefold()` возвращает `'возврат'`.

Оба метода создают **новую** чистую строку, поэтому мы сохраняем результат обратно в переменную `query`. В шаблоне функции `find_notes` эта строчка уже написана для вас.

---

## Шаг 2. Проверим одну строчку

Возьмём для пробы третий пункт регламента и спросим у Python: содержится ли в нём наш поисковый запрос?

```python
note = 'ВОЗВРАТ денег производится на карту покупателя.'
'возврат' in note.casefold()   # Результат: True (Да, содержится!)
```

Оператор `in` («внутри») проверяет, входит ли левая подстрока в правую. 

Обратите внимание: мы вызываем `.casefold()` только на время проверки. Сам исходный пункт в переменной `note` остаётся нетронутым — покупателю в ответе мы должны показать красивый оригинальный текст с правильными заглавными буквами, а не испорченную нижним регистром копию.

---

## Шаг 3. Переберём все строки одну за другой

Теперь объединим всё вместе. Нам нужно пройтись по всему списку `notes`, проверить каждую строку и сложить совпадения в отдельный список `selected` («отобранные»).

Для этого в Python используется цикл `for`:

```python
selected = []
for note in notes:
    if query in note.casefold():
        selected.append(note)
```

### Важно: отступы в Python имеют значение!
Пробелы в начале строк показывают структуру программы:
* `for` идёт без отступа.
* Строка `if` сдвинута вправо на 4 пробела — это значит, что проверка выполняется **внутри** цикла для каждой строки.
* Строка `selected.append(note)` сдвинута ещё на 4 пробела (всего 8) — это значит, что добавление произойдёт **только тогда**, когда условие `if` оказалось истинным.

Команда `.append(...)` берёт найденную строчку `note` и кладёт её в конец списка `selected`.

## Попробуйте «сломать» программу

Чтобы по-настоящему понять, как работает код, полезно намеренно сделать ошибку и посмотреть на реакцию:

1. **Уберите регистр:** временно сотрите `.casefold()` из условия `if` и запустите снова. Какой пункт исчез из результата и почему? Верните метод на место.
2. **Пустой запрос:** в файле `demo_search.py` замените поисковый запрос на три пробела: `query = '   '`. Запустите код. Программа немедленно выдаст понятную ошибку: `ValueError: Введите непустой запрос`.

Зачем в функции нужна эта строгая проверка? Пустая строка технически содержится в абсолютно любой строке текста! Если бы этой проверки не было, на случайный пустой запрос поиск вернул бы вообще весь регламент целиком. Когда поиском пользуется человек, пустой ввод кажется редкой оплошностью. Но когда запросы начнёт генерировать нейросеть, пустая строка может прийти из-за сбоя формата. Защитная проверка сразу выявит проблему, не дав мусору пойти дальше.

## Итог урока

Мы сделали первое и самое ответственное звено в будущей агентной системе:
* Если нужный пункт есть в базе знаний, но функция поиска его пропустила — модель никогда о нём не узнает и начнёт придумывать отсебятину.
* Теперь у вас есть инструмент, работу которого можно проверить отдельно от нейросети.

В профессиональной литературе такой предварительный отбор релевантных фрагментов называют словом **Retrieval** (извлечение данных). Это первая буква в аббревиатуре **RAG** (Retrieval-Augmented Generation). О том, как устроен RAG простыми словами, можно почитать в [памятке терминов](../terms.md#извлечение-данных-и-rag).

### Карта файлов в папке упражнения

```text

├── data/
│   └── refund_notes.txt   # Сам текстовый регламент возвратов (сырые данные)
├── notes.py               # Модуль с логикой работы с заметками (наша функция find_notes здесь!)
├── journal.py             # Модуль для записи логов и отчётов (понадобится в Уроке 3)
├── app.py                 # Главный дирижёр: свяжет чтение, поиск и запись в единый процесс (Урок 4)

└── demo.py                # Сквозной запуск всей цепочки целиком
```

### Зачем разделять код на разные файлы?
В хороших программах логику разделяют по ролям:
* `notes.py` умеет **только искать и читать текст**. Он ничего не знает о файлах журналов или кнопках запуска. Это «чистая логика».
* `journal.py` отвечает **только за сохранение результатов**.
* `app.py` не содержит внутри сложных алгоритмов — он лишь импортирует функции из `notes.py` и `journal.py` и командует: *«сначала прочитай, потом найди, потом сохрани»*.
* `demo_search.py` нужен нам для быстрой проверки: он создаёт маленький учебный список прямо в коде и передаёт его в `find_notes`.

### Анатомия функции `find_notes` строчка за строчкой

Давайте разберём каждую строчку из файла `notes.py`:

```python
def find_notes(notes: list[str], query: str) -> list[str]:
```
* `def` (от английского *define*) — ключевое слово Python: «объявляю новую функцию с именем `find_notes`».
* В скобках перечислены входящие данные (аргументы):
  * `notes: list[str]` — список строк регламента. Двоеточие и `list[str]` — это подсказка типа (type hint): функция ожидает список строк.
  * `query: str` — поисковая фраза (одна строка).
* `-> list[str]` — подсказка: функция обещает вернуть в ответ тоже список строк.

```python
    query = query.strip().casefold()
    if not query:
        raise ValueError('Введите непустой запрос')
```
* `if not query:` — проверка на пустоту. Если после отрезания пробелов в запросе ничего не осталось (длина 0), срабатывает `raise ValueError(...)`.
* `raise` — аварийный стоп-кран. Функция не пытается гадать, а прямо сообщает вызывающей программе: «мне передали некорректные данные».

```python
    selected = []
```
* Создаём пустой список-корзину `[]`, куда будем складывать найденные совпадения.

```python
    for note in notes:
        if query in note.casefold():
            selected.append(note)
    return selected
```
* Цикл перебирает элементы один за другим. Когда весь список `notes` просмотрен, `return selected` возвращает корзину с результатами тому, кто вызвал функцию (в нашем случае — скрипту `demo_search.py`).

### Как устроен скрипт запуска `demo_search.py`

Откройте `demo_search.py` — теперь вы легко поймёте всё, что там написано:

```python
from notes import find_notes   # 1. Приносим нашу функцию из соседнего файла notes.py

sample_notes = [               # 2. Готовим учебный список правил
    'Возврат товара возможен в течение 14 дней.',
    'Доставка по городу занимает 1 день.',
    'ВОЗВРАТ денег производится на карту покупателя.',
]

query = 'возврат'              # 3. Задаём слово для поиска

results = find_notes(sample_notes, query)  # 4. Вызываем функцию!
print(results)                             # 5. Печатаем на экран то, что она вернула
```

Никакой магии — всё работает прозрачно, по понятным правилам.

<details>
<summary>Бонус для любознательных: тот же поиск в одну строчку (list comprehension)</summary>

В Python есть элегантная сокращённая запись для фильтрации списков:
```python
return [note for note in notes if query in note.casefold()]
```
Она делает ровно то же самое, что наш цикл `for`: перебирает элементы и оставляет только подходящие. 

Если хотите проверить её в деле:
1. Откройте в `notes.py` заготовку второй функции `find_notes_alt`.
2. Замените строчку `raise NotImplementedError(...)` на `return [note for note in notes if query in note.casefold()]`.
3. Запустите `demo_search.py` — вторая строчка выдаст в точности такой же результат!
