# Урок 2. Читаем регламент из файла на диске

[Открыть исходники этого урока](../../exercises/lesson-01-02-read/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-01-02-read/TASK.md)

> **Где мы находимся:** Собираем умного помощника для регламента возвратов интернет-магазина. 
> 
> В Уроке 1 мы научили программу искать пункты по ключевому слову, но сам текст правил был «зашит» прямо в коде. В реальном бизнесе так никто не делает. 
> 
> Теперь мы делаем следующий шаг: научим программу аккуратно загружать регламент из настоящего текстового файла на диске:
> 
> `файл на диске -> [наше чтение] -> поиск -> модель -> ответ клиенту`

В реальных компаниях регламенты и базы знаний живут отдельно от программного кода: в текстовых файлах, Markdown-документах, базах данных или Confluence. И именно на этапе чтения документов чаще всего происходят скрытые и досадные поломки.

### История из жизни поддержки
Представьте ситуацию: клиент спрашивает бота: *«Как вернуть деньги за бракованный товар?»*, а бот отвечает: *«В правилах об этом ничего не сказано»*.

Почему бот так ответил? Есть два принципиально разных сценария:
1. **Проблема в данных:** Программа честно открыла регламент, прочитала его от корки до корки, но пункта о возврате брака там действительно нет. Кто виноват? Редактор документа. Нужно дополнить регламент в базе знаний.
2. **Проблема в инфраструктуре:** Программа даже не смогла открыть файл! Файл случайно переименовали, переложили в другую папку на сервере или у программы банально не хватило прав доступа (Permission Denied). Кто виноват? Системный администратор или разработчик.

Если программа на любую ошибку не глядя отвечает пользователю: *«Сведений не найдено»*, разработчики будут неделями обвинять составителей регламента, не понимая, что робот просто не может достучаться до файла. 

В этом уроке мы напишем модуль чтения так, чтобы эти две ситуации были чётко различимы.

## Шаг 1. Прочитаем файл целиком с помощью `Path`

В современном Python для работы с путями к файлам используют удобный объект `Path` из стандартной библиотеки `pathlib`:

```python
from pathlib import Path

path = Path('data/notes.txt')
text = path.read_text(encoding='utf-8')
```

1. `Path('data/notes.txt')` указывает, где именно на диске лежит файл.
2. Метод `.read_text(...)` открывает файл, полностью считывает всё его содержимое в память в виде одной большой строки и сам аккуратно закрывает файл.
3. Параметр `encoding='utf-8'` критически важен: на компьютерах с Windows без явного указания кодировки русские буквы часто превращаются в нечитаемые «кракозябры» (срабатывает системная кодировка cp1251). С `utf-8` всё прочитается корректно на любой операционной системе.

В нашей переменной `text` оказывается весь текст регламента. Символы перевода строки в нём представлены служебным символом `\n`.

## Шаг 2. Разрежем текст на отдельные строки

У строк в Python есть встроенный метод `.splitlines()`: он находит все переносы строк и нарезает текст на список отдельных строк:

```python
lines = text.splitlines()
```

Посмотрим на первые три элемента, которые вернул этот метод:

```python
# ['Возврат товара возможен в течение 14 дней.',
#  '  Доставка по городу занимает 1 день.',
#  '',
#  'ВОЗВРАТ денег производится на карту покупателя.',
#  ...]
```

Вот и ответ на нашу загадку: получилось **семь** элементов вместо шести!
* Пустая строка между пунктами превратилась в пустую строку `''`.
* Пробелы перед словом «Доставка» остались на месте.

Если скормить такой список поиску, поиск будет тратить ресурсы на перебор пустых строк, а неряшливые пробелы в итоге попадут в контекст модели.

## Шаг 3. Очистим каждую строку от мусора

Нам нужно перебрать все строки, отрезать пробелы по краям и оставить только непустые строки:

```python
cleaned_notes = []
for line in lines:
    cleaned_line = line.strip()
    if cleaned_line:
        cleaned_notes.append(cleaned_line)
```

Как это работает:
1. `line.strip()` убирает случайные пробелы и табуляции в начале и в конце строки (пробелы между словами внутри строки остаются нетронутыми).
2. `if cleaned_line:` — изящная проверка Python на непустоту. Пустую строку `""` Python воспринимает как `False` (ложь), а любую строку хотя бы с одним символом — как `True` (истина). Пустая строка просто не попадёт в условие `if`!
3. `cleaned_notes.append(cleaned_line)` кладёт чистую строчку в итоговый список.

### Разбор модуля `notes.py`: почему `Path` лучше обычных строк?

В старых уроках по Python часто можно встретить работу с файлами через обычные строки:
```python
# Старый стиль (легко ошибиться со слэшами на Windows/Linux):
with open('data/notes.txt', 'r', encoding='utf-8') as f:
    text = f.read()
```

В современной разработке стандарт де-факто — библиотека `pathlib.Path`:
```python
def read_notes(path: Path) -> list[str]:
    text = path.read_text(encoding='utf-8')
```

Преимущества `Path`:
* `Path` — это умный объект. Он автоматически ставит правильные слэши (обратные `\` на Windows и прямые `/` на Linux и macOS).
* Метод `.read_text()` сам открывает файл, читает его и гарантированно закрывает дескриптор, даже если при чтении случился сбой.
* Сигнатура `read_notes(path: Path)` сразу подсказывает разработчику: эта функция ждёт именно объект пути, а не произвольный текст.

### Как устроен скрипт запуска `demo_read.py`

Посмотрим на код `demo_read.py`:

```python
from pathlib import Path
from notes import read_notes

# Вычисляем абсолютный путь к папке, где лежит сам скрипт demo_read.py:
ROOT = Path(__file__).resolve().parent

def main():
    # Собираем надёжный путь к файлу: ROOT / 'data' / 'notes.txt'
    notes_file = ROOT / 'data' / 'notes.txt'
    result = read_notes(notes_file)
    print(result)

if __name__ == '__main__':
    main()
```

Обратите внимание на конструкцию:
```python
ROOT = Path(__file__).resolve().parent
```
* `__file__` — специальная переменная Python, содержащая путь к текущему исполняемому файлу.
* `.resolve()` — превращает путь в полный абсолютный путь (например, `D:\PROJECTS\...\lesson-01-02-read\demo_read.py`).
* `.parent` — берёт родительскую папку.
* Оператор `/` между объектами `Path` перегружен: запись `ROOT / 'data' / 'notes.txt'` элегантно склеивает части пути без необходимости писать громоздкие `os.path.join()`.

Благодаря этому скрипт запустится одинаково надёжно из любого места: хоть из PyCharm, хоть из терминала, хоть из дочернего процесса.

<details>
<summary>Бонус для любознательных: чтение и фильтрация одной строчкой</summary>

Как и в первом уроке, перебор и очистку строк можно записать через лаконичный list comprehension:

```python
cleaned_notes = [cleaned for line in lines if (cleaned := line.strip())]
```

Здесь используется «моржовый оператор» `:=` (walrus operator), появившийся в Python 3.8. Он прямо внутри условия очищает строку методом `line.strip()`, сохраняет её в переменную `cleaned` и проверяет, не пустая ли она. Если не пустая — добавляет в список. 

В продакшене часто пишут именно так, чтобы не раздувать простые функции.

</details>
