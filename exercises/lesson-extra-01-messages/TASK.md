# Как подготовить задачу для модели

Допустим, мы записали учебные заметки в текстовый файл и хотим найти среди них сведения о Python. Пользователь просит "Найди заметки о Python", модель запрашивает поиск, а Python-программа читает файл и возвращает найденные строки. Например, среди них может оказаться `Python lists keep item order.` - заметка о сохранении порядка элементов в списках.

Чтобы выбрать действие, модели нужны не только слова пользователя. Программа должна объяснить, какие инструменты существуют, как их запросить и что уже удалось сделать. Если результат поиска не вошёл в новые сообщения, модель его не увидит; если названия инструментов не объяснены, ответ может не соответствовать возможностям приложения.

Подготовкой сообщений займётся `build_decision_messages`, которую выделим из готовой `decide_live` файла `decisions.py`. Мы увидим точное содержимое будущего обращения: правила, задачу и историю. Это поможет разбирать поведение помощника по данным, которые действительно переданы модели. Сам запрос выполним в следующих дополнительных уроках, а здесь научимся проверять его состав.


Откройте decisions.py, функцию build_decision_messages.

В `decisions.py` замените заглушку в `build_decision_messages`. В шаблоне оставлены три места для вашей работы:

```python
def build_decision_messages(task: str, events: list[dict]) -> list[dict]:
    rules = RULES
    content = ...
    return [
        {'role': 'developer', 'content': ...},
        {'role': 'user', 'content': ...},
    ]
```

В первой строке с пропуском используйте показанный выше вызов `json.dumps`. В сообщение с ролью `'developer'` передайте переменную `rules`, а в сообщение с ролью `'user'` - переменную `content`. Удалите строку с `NotImplementedError`, когда заполните шаблон. Скобки `[...]` создают список, а два словаря внутри него сохраняют отдельные сообщения в нужном порядке.

Роль `'developer'` знакома нам по основным урокам. В готовом `transport.py` она будет заменена на `'system'` для выбранных подключений. Здесь сохраняем формат учебной программы; в сетевой модуль заглянем в третьем дополнительном уроке.

После заполнения функция должна отдать этот список тому коду, который её вызвал. В демонстрации это происходит в строке `messages = build_decision_messages('Найди заметки о Python', events)`: Python сначала выполнит функцию, а после её `return` сохранит список в `messages`. Поэтому следующий цикл в `demo_check.py` уже может читать сообщения и печатать их поля. Мы подготовили данные для модели, но ещё не отправили их; в заключительном уроке этот список передадим в `send_live`.


После реализации запустите demo_check.py через контекстное меню Run. Вывод находится внизу, во вкладке Run.
