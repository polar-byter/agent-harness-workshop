## 1. Карта первого подпроекта: как файлы общаются друг с другом

В папке `lesson-01-04-run` у вас лежит несколько файлов. Давайте снимем ощущение «чёрного ящика» и посмотрим, кто за что отвечает:

```text
lesson-01-04-run/
├── data/
│   └── notes.txt          # СЫРЫЕ ДАННЫЕ: обычный текстовый файл с правилами магазина
├── notes.py               # МОДУЛЬ 1: чистая работа с текстом (чтение файла и поиск строк)
├── journal.py             # МОДУЛЬ 2: инфраструктура (запись отчётов на диск в формате JSONL)
├── app.py                 # МОДУЛЬ 3: координатор (импортирует notes и journal, запускает процесс)
├── demo.py                # ПУЛЬТ УПРАВЛЕНИЯ: запускает app.run_search и выводит результат на экран
└── runs.jsonl             # РЕЗУЛЬТАТ РАБОТЫ: файл журнала, куда дописываются строки
```

### Схема взаимодействия:
```text
[demo.py] (Пульт управления)
    │
    ▼ вызывает функцию run_search(...)
[app.py] (Главный координатор)
    ├── 1. вызывает read_notes() ──► [notes.py] ──► читает data/notes.txt
    ├── 2. вызывает find_notes() ──► [notes.py] ──► ищет совпадения в памяти
    └── 3. вызывает write_result() ─► [journal.py] ─► дописывает в runs.jsonl
```

### Главный архитектурный принцип: Разделение ответственности (Separation of Concerns)
Обратите внимание на красоту такого разделения:
* `notes.py` **ничего не знает** о том, что результаты куда-то сохраняются. Он умеет только фильтровать и читать текст.
* `journal.py` **ничего не знает** о регламентах и возвратах. Он умеет лишь взять любой словарь и аккуратно дописать его в конец файла.
* `app.py` **не содержит внутри сложных алгоритмов**. Его работа — быть вежливым дирижёром: вовремя вызвать нужные функции и передать данные из одной в другую.

Если завтра вы захотите заменить текстовый файл `runs.jsonl` на базу данных PostgreSQL, вам придётся переписать только `journal.py` — файлы `notes.py` и логика поиска останутся абсолютно нетронутыми!

## 2. Разбор модуля notes.py: работа со строками и файлами

Откройте файл `notes.py`. В нём живут две главные функции: `find_notes` и `read_notes`.

### Функция `find_notes`: поиск по ключевому слову

```python
def find_notes(notes: list[str], query: str) -> list[str]:
    # Шаг 1: очищаем запрос
    query = query.strip().casefold()
    if not query:
        raise ValueError('Введите непустой запрос')
    
    # Шаг 2: готовим корзину для результатов
    matches = []
    
    # Шаг 3: перебираем все пункты правил
    for note in notes:
        if query in note.casefold():
            matches.append(note)
            
    # Шаг 4: возвращаем найденное
    return matches
```

#### Разбор строчка за строчкой:

1. `def find_notes(notes: list[str], query: str) -> list[str]:`
   * `notes: list[str]` — подсказка типа (type hint): функция ждёт на вход список строк (заметок).
   * `query: str` — поисковый запрос (одна строка).
   * `-> list[str]` — подсказка: функция обещает вернуть новый список строк.
   * *Для новичка:* Python сам по себе не запрещает передать другие типы данных, но эти аннотации помогают среде разработки (PyCharm) подсвечивать ошибки и давать вам автодополнение при наборе кода.

2. `query = query.strip().casefold()`
   * `.strip()` срезает случайные пробелы и табуляции в начале и в конце строки.
   * `.casefold()` приводит строку к нижнему регистру. Это более мощный аналог привычного `.lower()`, который идеально справляется со всеми символами кириллицы и спецсимволами других языков.
   * *Важно:* строки в Python **неизменяемы (immutable)**. Методы `.strip()` и `.casefold()` не меняют исходную строку на месте, а создают новую чистую копию. Поэтому мы сохраняем результат обратно: `query = ...`.

3. `if not query:`
   * В Python пустая строка `""` при проверке в `if` считается ложью (`False`).
   * Запись `if not query:` срабатывает, если длина строки равна нулю.
   * `raise ValueError('Введите непустой запрос')` — аварийный сигнал (исключение). Если пользователь или нейросеть прислали пустую строку, функция не пытается делать бессмысленную работу, а сразу останавливается и сообщает об ошибке.

4. `matches = []`
   * Создаём пустой список — «корзину», куда будем складывать найденные строки.

5. `for note in notes:`
   * Цикл `for` берёт элементы из списка `notes` по одному и на каждой итерации помещает текущий элемент в переменную `note`.

6. `if query in note.casefold():`
   * Оператор `in` проверяет, входит ли подстрока `query` в текст заметки.
   * Мы вызываем `.casefold()` у `note` только для проверки! Сам оригинальный пункт `note` остаётся с заглавными буквами.

7. `matches.append(note)`
   * Метод `.append(...)` кладёт оригинальную строку `note` в конец списка `matches`.

8. `return matches`
   * Возвращает собранный список наружу. 
   * *Обратите внимание на отступ:* `return` стоит на одном уровне с `for`. Если сдвинуть его вправо (внутрь цикла), функция завершится на самом первом же элементе!

### Функция `read_notes`: чтение файла с диска

```python
from pathlib import Path

def read_notes(path: Path) -> list[str]:
    text = path.read_text(encoding='utf-8')
    lines = text.splitlines()
    cleaned_notes = []
    for line in lines:
        cleaned_line = line.strip()
        if cleaned_line:
            cleaned_notes.append(cleaned_line)
    return cleaned_notes
```

#### Разбор ключевых моментов:

1. `from pathlib import Path`
   * `Path` — это современный объектно-ориентированный способ работы с файловыми путями.
   * В отличие от старых текстовых строк (`open("data/notes.txt")`), объект `Path` сам знает особенности операционной системы: ставит правильные слэши (`\` на Windows, `/` на Linux) и содержит удобные встроенные методы.

2. `text = path.read_text(encoding='utf-8')`
   * Метод `.read_text()` делает сразу три действия: безопасно открывает файл, считывает весь текст в память в одну большую строку и гарантированно закрывает файл.
   * `encoding='utf-8'` — железное правило для любого Python-разработчика под Windows. Если не указать кодировку явно, Windows откроет файл в древней системной кодировке `cp1251`, и весь русский текст превратится в нечитаемые символы.

3. `lines = text.splitlines()`
   * Метод нарезает большую строку на список отдельных строк по символам переноса (`\n` или `\r\n`).

4. `cleaned_line = line.strip()` и `if cleaned_line:`
   * Отрезаем пробелы по краям каждой строчки.
   * Проверка `if cleaned_line:` отсеивает пустые строки: если строка состояла только из пробелов, после `.strip()` она станет `""` и условие `if` её пропустит.

5. **Почему здесь нет `try...except FileNotFoundError`?**
   * Это важнейшее архитектурное решение: если файл на диске не существует, метод `.read_text()` выбросит системную ошибку `FileNotFoundError`.
   * Мы **намеренно не перехватываем её**! Если бы мы поймали её и вернули пустой список `[]`, вызывающая программа решила бы, что файл прочитан, но правил в нём нет. Отличие ошибки конфигурации (файл перенесён/удалён) от пустых данных — фундаментальное требование к надёжным системам.

## 3. Разбор модуля journal.py: логирование и формат JSONL

Откройте `journal.py`:

```python
import json
from pathlib import Path

def write_result(path: Path, result: dict) -> None:
    text = json.dumps(result, ensure_ascii=False)
    with path.open('a', encoding='utf-8') as stream:
        stream.write(text + '\n')
```

### Разбор строчка за строчкой:

1. `text = json.dumps(result, ensure_ascii=False)`
   * В памяти Python словарь `result` — это сложный объект: `{'query': 'возврат', 'status': 'found', ...}`.
   * Чтобы сохранить его в текстовый файл, его нужно перевести в строковый вид (сериализовать). Функция `json.dumps` (dump string) превращает структуру в строку JSON.
   * `ensure_ascii=False` — параметр, который запрещает превращать русские буквы в escape-коды вроде `\u0432\u043e\u0437`. С ним русский текст сохраняется человекочитаемым.

2. `with path.open('a', encoding='utf-8') as stream:`
   * Конструкция `with ... as ...` называется **контекстным менеджером**.
   * Она гарантирует: как только выполнение кода выйдет из блока `with` (даже если произойдёт сбой или аварийная остановка программы), Python автоматически вызовет закрытие файла и сбросит все буферы на диск.
   * Режим `'a'` (*append* — дозапись): курсор ставится в самый конец файла. Если файла ещё нет — Python создаст его. Если файл уже есть — новые данные допишутся в конец, не удаляя предыдущие записи!
   * Переменная `stream` (поток) — это объект открытого файла.

3. `stream.write(text + '\n')`
   * Записывает строчку JSON в файл и добавляет перенос строки `\n`.
   * Благодаря `\n` каждая запись живёт на своей отдельной строчке. Так получается формат **JSON Lines (JSONL)**.

## 4. Разбор модуля app.py: сборка оркестратора

Откройте `app.py`:

```python
from pathlib import Path
from notes import find_notes, read_notes
from journal import write_result

def run_search(notes_path: Path, query: str, journal_path: Path) -> dict:
    notes = read_notes(notes_path)
    matches = find_notes(notes, query)
    status = 'found' if matches else 'not_found'
    result = {
        'query': query.strip(),
        'status': status,
        'matches': matches,
    }
    write_result(journal_path, result)
    return result
```

### Разбор логики:

1. `from notes import find_notes, read_notes` и `from journal import write_result`
   * Модуль `app.py` не изобретает чтение, поиск и запись заново. Он просто «приносит» готовые инструменты из соседних файлов.

2. `status = 'found' if matches else 'not_found'`
   * Это **тернарный оператор** Python. Он эквивалентен записи:
     ```python
     if matches:
         status = 'found'
     else:
         status = 'not_found'
     ```
   * Если в списке `matches` есть хотя бы один элемент, он считается `True`, и статус будет `'found'`. Если список пуст (`[]`), он считается `False`, и статус будет `'not_found'`.

3. `result = { ... }`
   * Собираем предсказуемый словарь-контракт. Когда мы подключим нейросеть, модель получит именно этот понятный объект: запрос, статус и найденные строки.

4. `write_result(journal_path, result)`
   * Фиксируем событие в аудит-логе.

5. `return result`
   * Отдаём результат вызывающей программе.

## 5. Как устроен скрипт запуска demo.py

Посмотрим на демонстрационный файл `demo.py`:

```python
from pathlib import Path
from app import run_search

ROOT = Path(__file__).resolve().parent

def main():
    notes_path = ROOT / 'data' / 'notes.txt'
    journal_path = ROOT / 'runs.jsonl'
    query = ' возврат '
    
    result = run_search(notes_path, query, journal_path)
    print(result)

if __name__ == '__main__':
    main()
```

### Две важнейшие конструкции, которые должен знать каждый разработчик:

#### 1. Как надежно находить файлы: `ROOT = Path(__file__).resolve().parent`
* В новичковых скриптах часто пишут просто относительные пути: `Path('data/notes.txt')`.
* Опасность в том, что путь `data/notes.txt` отсчитывается от **текущей рабочей папки терминала**, а не от места, где лежит скрипт! Если вы запустите скрипт из другой папки, программа упадёт с `FileNotFoundError`.
* Конструкция `ROOT = Path(__file__).resolve().parent` вычисляет абсолютный путь к папке, где физически находится сам запускаемый файл.
* Запись `ROOT / 'data' / 'notes.txt'` всегда найдёт файл безошибочно, откуда бы вы его ни запустили.

#### 2. Зачем нужен блок `if __name__ == '__main__':`
* Когда вы запускаете файл напрямую кнопкой Run в PyCharm, специальная переменная `__name__` внутри файла принимает значение `'__main__'`.
* Условие `if __name__ == '__main__':` становится истинным, и функция `main()` выполняется.
* Но если завтра другой скрипт захочет импортировать какую-то функцию из этого файла (`from demo import ...`), переменная `__name__` будет равна имени модуля (`'demo'`). Условие `if` не сработает, и тестовый код не начнёт выполняться сам по себе при простом импорте!

## Резюме для новичка: золотые правила чистого кода

1. **Разделяйте логику и ввод-вывод:** функции, которые обрабатывают данные (`find_notes`), не должны сами открывать файлы и писать на экран через `print`.
2. **Всегда указывайте `encoding='utf-8'`** при чтении и записи текстовых файлов на диске.
3. **Используйте `pathlib.Path`** вместо текстовых строк для работы с путями.
4. **Не гасите системные ошибки молча:** если файл не найден — пусть программа упадёт с понятным `FileNotFoundError`, чем притворится, что всё в порядке.
5. **Логируйте в формате JSONL (append-only):** это предотвратит потерю истории при сбоях и позволит восстановить любой шаг работы вашего будущего ИИ-агента.
