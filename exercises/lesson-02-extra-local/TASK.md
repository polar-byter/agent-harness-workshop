# Подсказки к текущему заданию

> **Где мы.** В основном уроке программа отправляла сообщения в Ollama, а та запускала модель. Здесь попробуем загрузить модель в саму программу. Урок необязательный, основной маршрут продолжается через Ollama или облачный сервис.

До сих пор модель работала в отдельном приложении, а наш код только посылал ей запросы. Можно устроить иначе: загрузить файл модели прямо в программу на Python. Тогда загрузка модели, вызов и освобождение памяти становятся обязанностью нашего кода. Так бывает, например, когда модель встраивают в программу, которую нельзя подключать к сети.

Вопрос и данные возьмём прежние: "Сколько дней есть на возврат товара?" и пункт "Возврат товара возможен в течение 14 дней." Функции `build_messages` и `extract_answer` останутся без изменений: ответ модели мы приведём к знакомому формату. Напишем только `send_local` - функцию, которая вызывает загруженную модель.

Откройте `local_model.py` -> функция `send_local`.

## Напишите сами

Откройте `local_model.py`. У `send_local` два параметра: `model` - загруженный объект модели, `messages` - список сообщений. Строка `prepared = prepare_messages(messages)` уже есть. Замените следующую за ней строку `raise NotImplementedError(...)` фрагментом ниже и заполните два пропуска:

```python
    response = model.create_chat_completion(
        messages=...,
        max_tokens=256,
        temperature=0.7,
        top_p=0.8,
        top_k=20,
        min_p=0.0,
        presence_penalty=1.5,
    )
    return convert_response(...)
```

1. В `messages=` поставьте `prepared`.
2. В `convert_response(...)` передайте `response`.

`model.create_chat_completion(...)` - метод загруженной модели: он передаёт сообщения движку и возвращает словарь с результатом. HTTP-запроса и Ollama здесь нет, всё происходит внутри нашей программы. Код должен стоять внутри `send_local` с отступом в четыре пробела; `return` начинается на том же уровне, что `response = ...`.

`max_tokens=256` ограничивает длину ответа. Остальные настройки подобраны для Qwen, их не меняем, чтобы сравнивать способы подключения на одной задаче.

## Сначала проверим код, затем получим настоящий ответ

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Вместо модели здесь отвечает маленький подготовленный объект, поэтому файл GGUF и библиотека не нужны. Проверка убеждается, что функция передала правильные сообщения и вернула ожидаемую структуру. После реализации в Run будет:

```text
Проверка без модели: Вернуть товар можно в течение 14 дней.
```

Теперь откройте `demo.py` и выберите **Run 'demo'**. В Run появятся вопрос и пункт регламента, затем строка `Загружаем модель из файла...`. Дождитесь строки `Ответ модели:`; на скорость влияет мощность компьютера. Слова ответа могут отличаться от контрольного примера: проверьте, называет ли модель срок 14 дней и не добавляет ли сведений, которых нет в пункте.

Если видите `Допишите send_local...`, заглушка осталась на месте. Если программа просит положить файл модели по указанному пути, проверьте папку `models` и имя файла. Сообщение о незавершённой генерации значит, что модель упёрлась в лимит длины, и оборванный текст программа за ответ не выдаёт.
