# Урок 4. Сравниваем поведение на сценариях

[Открыть исходники этого урока](../../exercises/lesson-04-04-evaluation/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-04-04-evaluation/TASK.md)

> **Где мы.** Агент работает в ограниченном цикле, а его действия записываются в журнал. Последний шаг раздела: научиться проверять, стал ли агент лучше после изменения.
> `набор задач -> агент -> [сравнение с ожиданием] -> отчёт`

Допустим, вы поправили инструкцию, и помощник стал лучше отвечать на вопрос о сроке возврата. Значит ли это, что он стал лучше вообще? Он мог перестать сообщать "сведений нет", когда пункта в регламенте нет, или чаще упираться в лимит шагов. Удачный ответ на один вопрос легко заметить, а ухудшения на других без повторяемой проверки проходят мимо.

Поэтому подготовим набор сценариев и заранее, до запуска, договоримся, какой результат в каждом считается правильным. Функция `evaluate_cases` выполнит задачи, сравнит результаты с ожиданиями и соберёт отчёт. Аналитик получает в руки то, что обычно называют критериями приёмки: список случаев, по которым агента принимают в работу или отправляют на доработку.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-04-04-evaluation.zip?raw=true), распакуйте и откройте папку `lesson-04-04-evaluation` через **File -> Open**. Сегодняшнее задание - функция `evaluate_cases` в файле `control.py`.

## Посмотрим на данные

Один сценарий - словарь с названием, задачей и ожидаемым результатом:

```python
case = {'name': 'Обычный ответ', 'task': 'Найди пункты о возврате',
        'expected_status': 'completed', 'expected_answer': 'Готово'}
```

Список таких словарей придёт в параметр `cases`. Вместе с ним функция получит `run` - функцию, которая выполняет задачу и возвращает фактический результат со статусом и ответом. Его поля `status` и `answer` и будем сравнивать с ожиданием.

Точное сравнение работает только для коротких заранее оговорённых ответов. Поэтому в `demo.py` модель просят ответить одним словом: `found`, если пункты нашлись, и `missing`, если нет. Свободные формулировки так проверить нельзя, для них критерии придумывают иначе.

## Напишите сами

В `evaluate_cases` уже создан пустой список `results`. Замените `raise NotImplementedError(...)` кодом ниже и заполните пропуск:

```python
    for case in cases:
        actual = run(case['task'])
        passed = ...
        results.append({'name': case['name'], 'passed': passed})
    passed_count = sum(item['passed'] for item in results)
    return {'passed': passed_count, 'total': len(results), 'results': results}
```

В пропуск запишите два сравнения через `and`: `actual['status'] == case['expected_status']` и `actual['answer'] == case['expected_answer']`. Сценарий пройден, только если совпали оба поля. Двойное `==` сравнивает значения, одинарное `=` присваивает.

`run(case['task'])` вызывает переданную функцию так же, как `send(messages)` во втором разделе. `sum(...)` складывает логические значения: `True` считается единицей, `False` нулём, так получается число пройденных сценариев.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. В нём два сценария для настоящей модели. В первом она должна найти пункты о возврате и ответить `found`, во втором поиск строки `zzz_not_in_notes` должен закончиться ответом `missing`. Ваша функция сравнит фактические результаты с ожиданием.

**Угадайте до запуска:** пройдёт ли модель оба сценария?

`passed` может оказаться меньше `total`. Это не ошибка вашей функции, а результат проверки модели: например, она ответила полной фразой вместо одного слова. Один сценарий может занять несколько обращений к модели, учитывайте квоту сервиса.

## Проверим функцию отдельно

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Здесь поведение задано заранее, поэтому ожидаем:

```text
{'passed': 2, 'total': 2, 'results': [{'name': 'Ответ', 'passed': True}, {'name': 'Остановка', 'passed': True}]}
```

Второй сценарий проверяет остановку по лимиту: агент бесконечно просит читать регламент, и правильным результатом считается статус `budget_limit`. Для готовых проверок запустите `class LessonTests` в `tests/test_lesson.py`.

## Попробуйте сломать

В `demo_check.py` поменяйте в первом сценарии ожидаемый ответ `'Готово'` на `'Готово.'` с точкой и запустите снова. Сценарий провалится: для точного сравнения лишняя точка уже другой ответ. Именно поэтому для свободных ответов нужны другие критерии. Верните прежнее значение.

## Что мы получили

У помощника есть набор контрольных сценариев, по которым можно проверить любое изменение: новую инструкцию, другую модель, поправку в регламенте. Оценку поведения ИИ по заранее заданным критериям называют **эвалюацией**, по-английски evaluation или evals. Важно различать две проверки: тесты в `tests` проверяют, правильно ли ваш код считает результаты, а запуск `demo.py` проверяет, справилась ли модель со сценариями. Подробнее - в [памятке терминов](../terms.md#%D1%8D%D0%B2%D0%B0%D0%BB%D1%8E%D0%B0%D1%86%D0%B8%D1%8F).
