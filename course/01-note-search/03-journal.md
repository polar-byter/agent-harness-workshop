# Урок 3. Сохраняем результат поиска

[Открыть исходники этого урока](../../exercises/lesson-01-03-journal/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-01-03-journal/TASK.md)

> **Где мы.** Помощник читает регламент из файла и находит пункты по слову. Пока результат виден только в окне Run. Теперь научим программу записывать его в журнал.
> `файл -> чтение -> поиск -> [журнал]`

Представим, что вчера клиент получил неверный ответ о возврате, а сегодня вы разбираетесь, почему. Окно Run давно закрыто, и узнать, что тогда нашёл поиск, уже нельзя. Был ли нужный пункт среди найденных? С каким запросом вообще работал поиск? Без записи на эти вопросы не ответить, а это ровно те вопросы, с которых начинался случай MWS.

Поэтому каждый результат поиска будем записывать в файл: запрос и найденные пункты. Новую запись добавим в конец, чтобы прежние оставались на месте и их можно было сравнить.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-01-03-journal.zip?raw=true), распакуйте и откройте папку `lesson-01-03-journal` через **File -> Open**. Чтение и поиск из прошлых уроков в нём уже работают. Сегодняшнее задание - функция `write_result` в файле `journal.py`.

## Посмотрим на данные

Допустим, поиск по запросу "возврат" нашёл один пункт. Эти сведения собраны в словаре `result`: в нём по ключу `query` лежит запрос, а по ключу `matches` - список найденных пунктов. Чтобы записать словарь в текстовый файл, превратим его в строку в формате JSON:

```python
result = {'query': 'возврат', 'matches': ['Возврат товара возможен в течение 14 дней.']}
text = json.dumps(result, ensure_ascii=False)
# '{"query": "возврат", "matches": ["Возврат товара возможен в течение 14 дней."]}'
```

Функция `json.dumps` превращает словарь в одну строку текста, а `ensure_ascii=False` сохраняет русские буквы как есть. Без этого параметра вместо "возврат" в файле оказались бы коды вроде `в`. Каждая запись займёт в файле отдельную строку; такой формат называют JSONL, JSON Lines.

## Напишите сами

В `write_result` строка `text` уже готова. Осталось открыть файл журнала и дописать её в конец. Замените `raise NotImplementedError(...)` двумя строками и заполните пропуск:

```python
    with path.open('a', encoding='utf-8') as stream:
        stream.write(...)
```

В пропуск передайте `text + '\n'`: сам JSON и перевод строки после него. Без `'\n'` следующая запись приклеится к предыдущей, и журнал превратится в одну длинную строку.

Буква `'a'` в `path.open` означает режим добавления (append): новые строки пишутся в конец файла, а если файла ещё нет, он создаётся. Внутри блока `with` переменная `stream` обозначает открытый файл, а после выхода из блока Python сам его закроет. Возвращать ничего не нужно: результат этой функции - изменённый файл, а не значение.

## Запустим

Откройте `demo.py` в корне проекта, нажмите правой кнопкой в коде и выберите **Run 'demo'**. В окне Run появится последняя строка журнала:

```text
{"query": "возврат", "matches": ["Возврат товара возможен в течение 14 дней."]}
```

Рядом с `demo.py` появится файл `runs.jsonl`. Откройте его: там та же строка.

## Попробуйте сломать

1. Запустите `demo.py` ещё два раза и откройте `runs.jsonl`. Записей стало три, каждая на своей строке.
2. Замените в `write_result` букву `'a'` на `'w'` и запустите снова. В файле останется одна запись: режим `'w'` (write) каждый раз стирает файл. Для журнала это означало бы потерю всей истории. Верните `'a'`.

## Что мы получили

Когда поиском начнёт пользоваться модель, по такому журналу можно будет проверить, какие пункты она действительно получила. Для готовых проверок функции откройте `tests/test_lesson.py`, нажмите правой кнопкой на `class LessonTests` и выберите **Run**.
