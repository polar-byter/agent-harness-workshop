# Подсказки к текущему заданию

Чтобы ответить по заметке, нашей программе нужно выполнить цепочку действий: собрать сообщения, получить ответ и извлечь из него текст. Каждая часть уже подготовлена, но при соединении легко передать не те данные. Например, функция подключения ожидает список сообщений, а лишняя обёртка в словарь изменит договорённость между функциями.

Соберём обмен в `answer_question` и сначала проверим его на известном ответе из файла. Так ошибку передачи данных можно будет обнаружить до сетевого обращения. Затем заменим только способ получения ответа: подготовка сообщений и чтение результата останутся прежними.

Мы увидим на практике, как отделяют задачу приложения от подключения внешнего сервиса. Это поможет понимать, какой участок менять при выборе другого подключения и где искать ошибку: в содержимом запроса, в его отправке или в разборе ответа. Python здесь позволяет проследить каждое из этих действий на знакомых данных.

Откройте `assistant.py` -> функция `answer_question`.

Внутри `answer_question` подготовим сообщения через `build_messages`, получим ответ вызовом переданной функции `send` и извлечём текст через `extract_answer`. Правила сообщений и разбор структуры уже написаны, поэтому здесь мы только связываем эти действия.

Допишите уже начатую функцию по заготовке ниже, заполняя каждый `...` по подсказкам. Когда закончите, удалите строку `raise NotImplementedError(...)`; повторно добавлять заголовок `def` не нужно.

```python
def answer_question(question: str, notes: list[str], send) -> str:
    if not notes:
        return 'Подходящих заметок нет.'
    messages = build_messages(question, notes)
    response = ...
    answer = ...
    return answer
```

В первом пропуске вызовите `send(messages)`: в `send` уже находится функция, переданная из `demo.py`. Во втором передайте полученный `response` в `extract_answer`. Обратите внимание на порядок: передача функции как аргумента ещё не выполняет её; скобки с `messages` выполняют.

Если `notes` пуст, функция вернёт короткое сообщение раньше и `send` не вызовется. Так мы не обращаемся к модели без найденных источников. В учебном `demo.py` третьим аргументом передана `send_fixture`, которая читает `response.json`. Для настоящего запроса передадим `send_live`. В обоих случаях `answer_question` вызовет полученную функцию через параметр `send`: менять подготовку сообщений и извлечение текста не потребуется.

Проследим, что получится при нашем запуске. Сначала `messages` содержит правила, вопрос и заметку; затем `send(messages)` возвращает словарь с ответом. Вызов `extract_answer(response)` достаёт из него строку `Списки Python сохраняют порядок элементов.`, а `return` передаёт её из `answer_question` обратно в `demo.py`. Поэтому переменная `result` в демонстрации хранит готовый текст ответа, который можно напечатать. Внутри упражнения ответ читается из файла; после подключения модели тот же путь данных начинается с настоящего запроса.
