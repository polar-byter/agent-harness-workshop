# Урок 3. Применяем согласованное предложение

[Открыть исходники этого урока](../../exercises/lesson-05-03-apply/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-05-03-apply/TASK.md)

> **Где мы.** Агент предложил правку, программа показала её человеку в виде diff. Теперь запишем правку в файл, но только с согласия человека.
> `предложение -> diff -> [согласие -> проверка хеша -> запись] -> проверка тестами`

Показать правку ещё не значит получить разрешение её записать. Есть и вторая ловушка: пока человек смотрел diff, файл мог измениться, например коллега поправил его вручную. Тогда показанная правка относится уже к другой версии кода, и запись затрёт чужую работу.

Поэтому функция `apply_change` запишет файл при двух условиях: человек согласился, и файл до сих пор совпадает с той версией, для которой готовилось предложение. При отказе файл останется прежним, а если хеш не совпадёт, программа остановится с ошибкой. Согласие становится частью выполнения программы, а не просто фразой в диалоге с моделью.

## Откроем каркас

Скачайте [архив урока](../../downloads/lesson-05-03-apply.zip?raw=true), распакуйте и откройте папку `lesson-05-03-apply` через **File -> Open**. Сегодняшнее задание - функция `apply_change` в файле `workspace.py`.

## Посмотрим на данные

В `demo.py` программа показывает diff и спрашивает в окне Run, применить ли правку. Ответ превращается в `approved`: `True`, если вы ввели `да`, и `False` при любом другом ответе. Предложение из прошлого урока приходит в словаре `proposal` с полями `path`, `before_hash`, `new_text` и `diff`.

При `approved=False` функция сразу возвращает `False` и файл не трогает. При согласии она вычисляет хеш файла сейчас, сравнивает его с `proposal['before_hash']` и только при совпадении записывает `new_text`.

## Напишите сами

В `apply_change` уже есть строка с проверенным путём. Перед ней добавьте ранний выход при отказе, а вместо `raise NotImplementedError(...)` - проверку хеша и запись. Целиком функция выглядит так, заполните пропуск:

```python
    if not approved:
        return False
    path = workspace_path(root, proposal['path'])
    current_hash = hashlib.sha256(path.read_bytes()).hexdigest()
    if current_hash != proposal['before_hash']:
        raise ValueError('Файл изменился после подготовки предложения')
    path.write_text(..., encoding='utf-8')
    return True
```

В `write_text` передайте `proposal['new_text']` - тот самый новый текст, который человек видел в diff. Сам `diff` для записи не годится: в нём служебные строки с `+`, `-` и `@@`, а файлу нужен обычный код. `write_text` заменяет всё содержимое файла, поэтому согласие и проверка хеша стоят до неё.

Функция возвращает `True`, если правка записана, и `False`, если человек отказал. Это значение сообщает вызывающему коду, что произошло с файлом. Правильность нового кода оно не подтверждает: это проверим тестами в следующем уроке.

## Запустим с моделью

Откройте `demo.py` и выберите **Run 'demo'**. Программа получит предложение модели и покажет diff, а внизу, в Run, появится вопрос о применении. Для первого раза просто нажмите Enter: запись должна быть отклонена, и программа напечатает `Изменение применено: False`. Затем запустите ещё раз, внимательно прочитайте diff и, если согласны с правкой, щёлкните после вопроса, введите `да` и нажмите Enter.

## Проверим функцию отдельно

Откройте `demo_check.py` и выберите **Run 'demo_check'**. Ожидаем diff и затем `False`: в контрольном запуске согласие не дано, и файл не меняется. Для готовых проверок запустите `class LessonTests`.

## Попробуйте сломать

Запустите `demo.py`, дождитесь вопроса о применении, но пока не отвечайте. Откройте `workspace/prices.py`, добавьте в конце пустую строку и сохраните. Теперь вернитесь в Run и введите `да`. Программа остановится с ошибкой "Файл изменился после подготовки предложения": хеш файла уже не совпадает с тем, что было при показе diff. Уберите добавленную строку.

## Что мы получили

Правка агента попадает в файл только с согласия человека и только в ту версию, которую человек видел. Участие человека в работе агента в такой точке называют **human-in-the-loop**, сокращённо HITL. Здесь человек не просматривает результат после завершения, а принимает решение по ходу выполнения, и его отказ действительно останавливает запись. Так задаётся, какие действия агент делает сам, а какие требуют решения человека. Подробнее - в [памятке терминов](../terms.md#%D1%83%D1%87%D0%B0%D1%81%D1%82%D0%B8%D0%B5-%D1%87%D0%B5%D0%BB%D0%BE%D0%B2%D0%B5%D0%BA%D0%B0).
