## Посмотрим на данные

В нашем учебном протоколе команда — обычный словарь. Поле `tool` называет операцию, `query` содержит запрос поиска. Поддержим только `read_notes` и `find_notes`; путь к файлу задаёт приложение через `notes_path`. Модель не выбирает произвольный файл на диске.

```python
command = {'type': 'tool', 'tool': 'find_notes', 'query': 'python'}
command.get('tool')  # 'find_notes' 
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

Значение `"find_notes"` в команде — пока просто текст. Python не должен выполнять его сам по себе. Мы явно сравним имя с двумя разрешёнными вариантами и вызовем соответствующую готовую функцию. Такой выбор по имени программисты называют диспетчеризацией.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть — вторую функцию с тем же именем создавать не нужно.

```python
def dispatch_tool(command: dict, notes_path: Path) -> dict:
    name = command.get('tool')
    if name == 'read_notes':
        return {'notes': ...}
    if name == 'find_notes':
        query = command.get('query')
        if not isinstance(query, str):
            raise ValueError('Для поиска нужна строка query')
        notes = read_notes(notes_path)
        return {'matches': ...}
    raise ValueError('Неизвестный инструмент: ' + str(name))
```

В ветке `read_notes` подставьте вызов `read_notes(notes_path)`. В ветке поиска заметки уже прочитаны в `notes`; передайте их вместе с `query` в `find_notes`. Мы используем существующие функции, а не дублируем их код.

`command.get("tool")` достаёт имя операции; если ключа нет, получится `None`, и команда попадёт в последнюю ошибку. `isinstance(query, str)` проверяет, что вместо запроса нам не передали число или список. Имя файла берём только из `notes_path`, который задаёт приложение.

## Найдём файл запуска и проверим результат

В левой панели **Project → lesson-03-01-tools → demo.py** откройте файл двойным щелчком. Нажмите правой кнопкой внутри открытого редактора и выберите **Run 'demo'**. Внизу появится окно **Run** с выводом именно этого файла. Отдельная общая кнопка «запустить проект» нам здесь не нужна: выбираем конкретный демонстрационный файл. Если панель с файлами скрыта, вернитесь к **View → Tool Windows → Project**. Если Run скрыто — **View → Tool Windows → Run**.

До завершения функции появится сообщение «Допишите … по подсказкам урока». После реализации ожидаем:

```text
{'matches': ['Python functions return values.', 'Python lists keep item order.']}
```

Для дополнительного контроля откройте в этом же проекте `tests/test_lesson.py`, найдите `class LessonTests`, нажмите правой кнопкой по имени класса и выберите Run. Это необязательная проверка текущего задания; внутреннее устройство тестов сейчас разбирать не нужно.

Сейчас ваша работа — `dispatch_tool` в `agent.py`; затем повторный запуск `demo.py`.
