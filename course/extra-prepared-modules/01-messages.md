# Как подготовить задачу для модели

[Открыть исходники этого урока](../../exercises/lesson-extra-01-messages/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-extra-01-messages/TASK.md)

Допустим, мы записали учебные заметки в текстовый файл и хотим найти среди них сведения о Python. Пользователь просит "Найди заметки о Python", модель запрашивает поиск, а Python-программа читает файл и возвращает найденные строки. Например, среди них может оказаться `Python lists keep item order.` - заметка о сохранении порядка элементов в списках.

Чтобы выбрать действие, модели нужны не только слова пользователя. Программа должна объяснить, какие инструменты существуют, как их запросить и что уже удалось сделать. Если результат поиска не вошёл в новые сообщения, модель его не увидит; если названия инструментов не объяснены, ответ может не соответствовать возможностям приложения.

Подготовкой сообщений займётся `build_decision_messages`, которую выделим из готовой `decide_live` файла `decisions.py`. Мы увидим точное содержимое будущего обращения: правила, задачу и историю. Это поможет разбирать поведение помощника по данным, которые действительно переданы модели. Сам запрос выполним в следующих дополнительных уроках, а здесь научимся проверять его состав.

## Что именно мы передадим модели

Начнём с первого обращения, когда программа ещё ничего не искала. В переменной `task` сохраним просьбу пользователя, а в `events` - историю выполненных действий. Пока таких действий нет, поэтому история будет пустым списком:

```python
task = 'Найди заметки о Python'
events = []
```

В вызове `build_decision_messages(task, events)` эти значения попадут в параметры с такими же именами. Функция вернёт два сообщения. Поле `role` указывает назначение сообщения: в нашем формате роль `'developer'` отведена правилам приложения, а `'user'` - задаче и её данным. Поле `content` содержит текст сообщения. Правила уже записаны в переменной `RULES` в начале `decisions.py`. Среди них есть образец того, как модель должна запросить поиск:

```json
{"type":"tool","tool":"find_notes","query":"слово"}
```

В этой записи `type: "tool"` обозначает запрос действия, `tool: "find_notes"` называет функцию поиска, а поле `query` содержит искомый текст. Слово "слово" здесь служит образцом: для нашей задачи ожидаем запрос `"python"`. Так мы объясняем модели, в каком виде программа ждёт команду.

В показанном объекте JSON данные записаны в виде полей с именами и значениями; в следующем уроке мы превратим такой текст в Python-словарь. Пока достаточно различать инструкцию с образцом и ответ, который модель ещё должна дать. Сам образец ничего не выполняет и не гарантирует правильный ответ. Здесь модель возвращает обычный текст, который мы просим оформить как JSON, а программа сама проверяет его и выполняет разрешённое действие.

Перед отправкой преобразуем задачу и историю действий из Python-словаря в строку JSON:

```python
content = json.dumps({'task': task, 'events': events}, ensure_ascii=False)
```

`json.dumps` получает Python-словарь и возвращает строку. Параметр `ensure_ascii=False` оставляет русские буквы читаемыми. В `content` получится текст `{"task": "Найди заметки о Python", "events": []}`. Именно строку, а не вложенный словарь, запишем в поле `content` второго сообщения.

## Соберём функцию с подсказками

В `decisions.py` замените заглушку в `build_decision_messages`. В шаблоне оставлены три места для вашей работы:

```python
def build_decision_messages(task: str, events: list[dict]) -> list[dict]:
    rules = RULES
    content = ...
    return [
        {'role': 'developer', 'content': ...},
        {'role': 'user', 'content': ...},
    ]
```

В первой строке с пропуском используйте показанный выше вызов `json.dumps`. В сообщение с ролью `'developer'` передайте переменную `rules`, а в сообщение с ролью `'user'` - переменную `content`. Удалите строку с `NotImplementedError`, когда заполните шаблон. Скобки `[...]` создают список, а два словаря внутри него сохраняют отдельные сообщения в нужном порядке.

Роль `'developer'` знакома нам по основным урокам. В готовом `transport.py` она будет заменена на `'system'` для выбранных подключений. Здесь сохраняем формат учебной программы; в сетевой модуль заглянем в третьем дополнительном уроке.

После заполнения функция должна отдать этот список тому коду, который её вызвал. В демонстрации это происходит в строке `messages = build_decision_messages('Найди заметки о Python', events)`: Python сначала выполнит функцию, а после её `return` сохранит список в `messages`. Поэтому следующий цикл в `demo_check.py` уже может читать сообщения и печатать их поля. Мы подготовили данные для модели, но ещё не отправили их; в заключительном уроке этот список передадим в `send_live`.

## Посмотрим результат и изменим историю

В корне `lesson-extra-01-messages` найдите `demo_check.py`, щёлкните по нему правой кнопкой и выберите **Run**. Вывод появится внизу, во вкладке **Run**. До реализации там будет просьба дописать функцию; после неё увидим правила, а затем задачу с пустым списком `events`.

`demo.py` повторяет этот опыт без сети; для текущего шага достаточно одного запуска.

После удачного запуска можно открыть `tests/test_lesson.py` и выбрать **Run** у имени файла. Эти необязательные проверки помогают сохранить договорённости о данных, если позже вы измените реализацию.

В `demo_check.py` уже подготовлен второй вызов. Представим, что программа выполнила поиск и собирается снова обратиться к модели. Задача остаётся прежней, а в историю добавляется запись: какой инструмент работал и что он вернул. Для наглядности в этом примере оставим одну найденную строку:

```python
events = [{'tool': 'find_notes', 'result': ['Python lists keep item order.']}]
```

Здесь поле `tool` хранит имя выполненного инструмента, а `result` - список найденных строк. Эту запись подготовила бы программа после поиска; модель сама её не создаёт. Сравните два напечатанных сообщения с ролью `'user'`: во втором модель получила бы найденную строку вместе с исходной задачей. Правила при этом не изменились. Мы ещё не выяснили, что ответит модель, зато видим, какие сведения ей собирается отправить программа.
