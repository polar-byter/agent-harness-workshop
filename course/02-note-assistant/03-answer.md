# Урок 3. Соединяем запрос и ответ

[Открыть исходники этого урока](../../exercises/lesson-02-03-answer/README.md) / [Подсказки рядом с кодом](../../exercises/lesson-02-03-answer/TASK.md)

> **Где мы находимся:** У нас готовы два компонента:
> 1. `build_messages` умеет собирать вопрос и заметки в сообщения.
> 2. `extract_answer` умеет извлекать чистый текст из ответа сервиса.
> 
> Теперь мы объединим их в одну главную функцию - `answer_question` в файле `assistant.py`. Она принимает функцию отправки запроса как аргумент и содержит критическую оптимизацию бюджета:
> 
> `[вопрос + заметки] -> проверка непустоты -> build_messages -> send(...) -> extract_answer -> итоговый ответ`

---

## Главная экономия токенов: быстрый выход без заметок

Представьте ситуацию: клиент спрашивает: *"Есть ли у вас доставка на Луну?"*.
Поисковая функция `find_notes` добросовестно просмотрела регламент и вернула пустой список: `notes = []`.

Что делает плохая программа? Она формирует промпт, делает платный сетевой запрос к модели, тратит 2-3 секунды времени и деньги на токены только для того, чтобы модель ответила: *"В правилах ничего нет"*.

Что делает умный harness?
Если список заметок пуст (`not notes`), функция **вообще не вызывает модель**! Она мгновенно возвращает клиенту стандартное вежливое сообщение:
> *"В регламенте нет сведений по вашему вопросу."*

Вы экономите деньги, снижаете нагрузку на инфраструктуру и отвечаете клиенту за 1 миллисекунду.

## Напишите код сами

Откройте `assistant.py` и найдите функцию `answer_question`:

```python
def answer_question(question: str, notes: list[str], send) -> str:
    raise NotImplementedError("Допишите answer_question по подсказкам урока")
```

Замените строчку `raise NotImplementedError(...)` следующим кодом и заполните три пропуска `...`:

```python
    if not ...:
        return 'В регламенте нет сведений по вашему вопросу.'
        
    messages = build_messages(..., notes)
    raw_response = send(...)
    return extract_answer(raw_response)
```

1. В первом `if not ...:` проверьте список заметок: `notes`.
2. В функцию `build_messages` передайте входящий вопрос: `question`.
3. В переданную функцию `send(...)` отправьте подготовленный список: `messages`.

## Под капотом: паттерн "Передача функции как аргумента" (Dependency Injection)

Обратите внимание на третий параметр: `send`.
Мы не зашили сетевой вызов жестко внутрь `assistant.py`. Мы передаем функцию `send` снаружи!

Зачем это нужно?
* В тестах мы передаем быструю фикстуру `send_fixture`, которая читает локальный JSON и не требует интернета.
* В боевом режиме мы передадим сетевой адаптер `send_live`, который отправляет реальные HTTP-запросы в Ollama или облако.
* Логика нашего ассистента в `assistant.py` остается чистой и абсолютно не зависит от сетевых библиотек!
