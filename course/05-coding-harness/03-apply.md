## Посмотрим на данные

`approved` - логическое значение: `True` означает согласие, `False` - отказ. `proposal` содержит исходный хеш и предлагаемый текст. При отказе вернём `False`, при успешной записи - `True`. Если файл изменился, старое предложение применять нельзя.

```python
approved = False
# После просмотра предложения читатель сам может выбрать True в demo.py.
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Такой фиксированный пример используется в `demo_check.py`; в основном `demo.py` данные поступают из настоящего запуска. Их фактические значения увидим в Run.

## Соберём функцию с подсказками

У программы есть предложение, но пока нет разрешения его применять. Начнём с отказа: если `approved` равно `False`, сразу вернём `False` и не будем писать файл. Для разрешённого изменения сначала убедимся, что исходный файл всё ещё совпадает с тем, для которого показывали diff.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть - вторую функцию с тем же именем создавать не нужно.

```python
def apply_change(root: Path, proposal: dict, approved: bool) -> bool:
    if not approved:
        return False
    path = workspace_path(root, proposal['path'])
    current_hash = hashlib.sha256(path.read_bytes()).hexdigest()
    if current_hash != proposal['before_hash']:
        raise ValueError('Файл изменился после подготовки предложения')
    path.write_text(..., encoding='utf-8')
    return True
```

В `write_text` передайте `proposal["new_text"]` - уже показанный новый текст. Не используйте вместо него `diff`: в diff есть служебные строки, а Python-файлу нужен обычный исходный код. `write_text` заменяет всё содержимое выбранного файла, поэтому согласие и проверка хеша идут раньше.

В каркасе пока найден путь, но для полноценной функции добавьте ранний отказ перед этой строкой, как показано выше. Затем сравните хеши и допишите запись. В `demo.py` сначала оставьте `approved = False`; после просмотра diff можно осознанно выбрать `True`. Речь идёт только о приложенном учебном `workspace/prices.py`.

## Запустим с нашей моделью

После реализации откройте **Project -> lesson-05-03-apply -> demo.py**, щёлкните правой кнопкой внутри редактора и выберите **Run 'demo'**. Результат появится в панели **Run**; её можно открыть через **View -> Tool Windows -> Run**.

Программа получит предложение модели и покажет diff. Затем внизу, в **Run**, появится вопрос о применении. Щёлкните после вопроса, введите `да` и нажмите Enter, только если согласны с показанной правкой. Любой другой ответ означает отказ. Ваша `apply_change` должна учесть этот выбор и проверить, что исходный файл не менялся после подготовки предложения. Для первого запуска можно просто нажать Enter и убедиться, что запись отклонена.

Если настройки ещё не сохранены или перестали работать, вернитесь к [уроку подключения модели](../02-note-assistant/04-connect.md). В этом запуске модель не подменяется ответом из файла. Маленькая локальная модель может плохо соблюдать формат JSON; сначала отличите ошибку разбора её ответа от ошибки вашей функции. Если подключение работает, но возможностей модели не хватает, смените модель через `configure_model.py`, сохранив реализацию задания.

## Проверим функцию отдельно

Для воспроизводимого примера откройте **Project -> lesson-05-03-apply -> demo_check.py** и выберите **Run 'demo_check'**. Этот файл обращается к подготовленным данным без модели. До завершения текущей функции он показывает «Допишите ...», после реализации ожидаем:

```text
Сначала diff, затем False: при approved = False файл не изменён. После осознанной смены на True файл получит исправление.
```

Дополнительно можно запустить `tests/test_lesson.py` через Run по классу `LessonTests`. Эти проверки помогают обнаружить ошибку функции независимо от поведения модели.
