## Посмотрим на данные

`decide(task, events)` возвращает команду или окончательный ответ. `events` хранит пары «команда - результат», а `max_steps` ограничивает число обращений за решением. В учебном режиме решение выдаёт подготовленная функция `decide_fixture`, поэтому запуск воспроизводим. Настоящая модель подключается отдельным адаптером.

```python
events = []
events.append({'command': {'tool': 'find_notes', 'query': 'python'},
               'result': {'matches': ['Python lists']}})
```

Этот фрагмент поясняет данные и конструкции; в учебный модуль его целиком копировать не требуется. Рабочие значения уже подготовлены в `demo.py`.

## Соберём функцию с подсказками

Сначала разберём, что меняется между двумя шагами. На первом `events` пуст: учебная функция `decide` просит поиск. Наш код выполняет его и добавляет результат в историю. На следующем шаге `decide` получает уже эту историю и может вернуть ответ. Если мы забудем добавить событие, решающая функция не узнает, что поиск состоялся.

В файле текущего задания уже есть начало функции. Допишите её по заготовке ниже: `...` обозначает место для вашего выражения, а не готовую команду. Когда заполните пропуски, удалите строку `raise NotImplementedError(...)` из каркаса. Заголовок `def` в файле уже есть - вторую функцию с тем же именем создавать не нужно.

```python
def run_agent(task: str, notes_path: Path, decide, max_steps: int = 4) -> dict:
    if max_steps < 1:
        raise ValueError('Нужен хотя бы один шаг')
    events = []
    for step in range(max_steps):
        command = decide(task, events)
        if command.get('type') == 'answer':
            text = command.get('text')
            if not isinstance(text, str) or not text.strip():
                raise ValueError('Пустой ответ')
            return {'status': 'completed', 'answer': text, 'events': events}
        if command.get('type') != 'tool':
            raise ValueError('Ожидался ответ или запрос инструмента')
        result = ...
        events.append({'command': ..., 'result': ...})
    return {'status': 'step_limit', 'answer': '', 'events': events}
```

В `result` сохраните `dispatch_tool(command, notes_path)`. В событие положите переменные `command` и `result`: так следующий вызов `decide(task, events)` получит и запрос операции, и найденные данные.

`range(max_steps)` ограничивает количество повторений. При `max_steps=4` цикл сможет четыре раза запросить следующее действие. `return` внутри ветки `answer` завершает всю функцию сразу. Последний `return` расположен после цикла: он выполняется только тогда, когда шаги закончились без окончательного ответа. Проверки типов команд уже показаны в заготовке, чтобы вы могли сосредоточиться на обмене данными.

## Когда будете готовы подключить модель

Пока `demo.py` использует подготовленный ответ или учебную функцию выбора действий. Это проверяет наш код, но не показывает качество настоящей модели. В этом же корне есть `demo_live.py` - отдельный сетевой запуск.

Для него нужны действующий доступ к API и выбранная доступная вам модель. В PyCharm откройте файл `demo_live.py`, создайте его конфигурацию через контекстное меню Run, затем откройте **Run -> Edit Configurations**. В настройке этого файла найдите **Environment variables** (при необходимости через **Modify options**) и задайте `OPENAI_API_KEY` и `OPENAI_MODEL`. Первое - ключ вашего аккаунта, второе - точное имя выбранной модели. Не вставляйте ключ в Python-файл или архив. Если доступа ещё нет, учебный маршрут можно продолжить с подготовленными ответами.

После настройки отдельно запустите `demo_live.py`. Он отправляет запрос в OpenAI Responses API через готовый `transport.py`; сетевой вызов расходует доступный бюджет API. Текст реального ответа заранее не фиксирован. Ошибку доступа или соединения разбираем отдельно: она не означает, что файл с заметками пуст. Другой сервис потребует своего адаптера. Эти архивы проверены локально; сетевые ответы при их подготовке не запрашивались.

Сейчас ваша работа - `run_agent` в `agent.py`; затем повторный запуск `demo.py`.
